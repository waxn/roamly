# Explicit resolution for requirements.txt.
#
# requirements.txt expresses INTENT (Django>=6.0,<7.0). This file freezes what
# that intent resolves to, so a rebuild is reproducible and an upgrade is a
# reviewable diff with a revert path. Before this existed there was no lockfile
# of any kind, which meant two rebuilds of the same commit could produce
# different images and several majors could land silently on a `--build`.
#
# To upgrade: edit a version here, rebuild, verify, commit. To roll back:
# git revert that commit and rebuild.
#
# DIRECT dependencies only. Transitive deps deliberately float — pinning a full
# dependency tree would need a real resolver (pip-tools/uv), and a partial file
# that claims to be complete is worse than one that says what it covers.
#
# Verified against PyPI 2026-09-15.
