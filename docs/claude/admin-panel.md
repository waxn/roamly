# Admin panel and site config

_Read when: Admin accounts, admin panel tabs, custom JS, contact form._

**Admin accounts:** `UserProfile.is_admin` marks an instance admin (distinct from `is_staff`/`is_superuser`). Migration `0028` backfills `is_admin=True` for pre-existing accounts. **The first account created on an instance is always an admin** (`signup_view` counts `AuthUser.objects.exists()` before `form.save()`), because otherwise a fresh install has no admin and no way to make one: `ADMIN_SIGNUP_KEY` was the only other route, and it is an env var `docker-compose.yml` must enumerate explicitly — an admin who hadn't set it before their first signup was locked out of `/admin-panel/` permanently. Later signups can still register as admins via the signup form's `<details>` section using `ADMIN_SIGNUP_KEY` (validated in `SignUpForm.clean_admin_key`; section only shows when env key is set, and it is now plumbed through `.env.example` + `docker-compose.yml.example`), or be promoted from Admin Panel → Users. Exposed to templates as `IS_ADMIN` by `tracker.context_processors.custom_js_snippet`.

**Admin panel** (`/admin-panel/`, `admin_panel_view` → `admin_panel.html`, admin-only): ten client-side tabs — **Monitoring**, **Access Log**, **Events**, **Retention** (all logging, below), **Users** (list every account; toggle `is_admin`; delete another user and all their data), **Custom JS** (edit the instance snippet), **Contact** (contact address), **CAPTCHA** (Turnstile config, below), **Basemaps** (CARTO basemap API key + the basemap catalog and provider keys, below), **Downloads** (road/subway/POI data — below). User endpoints: `GET /api/admin/users/`, `POST /api/admin/users/<id>/toggle-admin/`, `POST /api/admin/users/<id>/delete/`, plus the **Edit** dialog's `GET /api/admin/users/<id>/` + `POST /api/admin/users/<id>/update/` (`admin_update_user_api`). Edit exists for the locked-out user: it changes username / email (same case-insensitive uniqueness as `SignUpForm.clean_email`), `email_verified`, `is_active` (blocked on yourself), sets a password (`validate_password`; `set_password` rotates the session hash, so they are signed out everywhere), and offers three one-shot recovery levers — `disable_totp` (clears secret + backup codes), `forget_devices` (`KnownDevice`), `send_reset` (the standard reset link, SMTP-gated). Every key is optional and only what is present changes. **2FA can only be turned off there, never on** — enabling needs the user's own authenticator app. Each save writes one `admin_edit_user` `ActionLog` row (migration `0098`, choices-only) listing what changed. All guarded by `_require_admin`. Tabs support deep-linking via a URL hash matching the tab name (e.g. `/admin-panel/#downloads`) — read once on page load, since nothing else in this file uses `location.hash` for routing.


**Analytics / custom JS:** Instance-wide HTML injected verbatim before `</body>` via `{{ CUSTOM_JS_SNIPPET|safe }}` (paste snippets as-given, including their `<script>` tags). Lives in the `SiteConfig` singleton (`SiteConfig.load()`, pk=1), edited from **Admin Panel → Custom JS** (admin-only, `POST /api/site/custom-js/`). The `custom_js_snippet` context processor exposes `CUSTOM_JS_SNIPPET` to **every** template, but the injection line must exist in each top-level template: `base.html` (all app pages) **and** the standalone public templates that don't extend it — `landing.html`, `login.html`, `signup.html`, `docs.html`, `privacy.html`, `terms.html`. Analytics must reach the public pages, so any new standalone template needs the injection line too. `context_processors.get_custom_js()` reads it cached (`site_custom_js`, 1h TTL); the save endpoint busts that key.

**Contact address + form.** `SiteConfig.contact_email` (migration `0047`, admin-only, edited from **Admin Panel → Contact**, `POST /api/site/contact-email/`) drives a **contact** link in the footer of the landing and settings pages. The context processor exposes it cached as `CONTACT_EMAIL` (`site_contact_email` key, 1h TTL, busted on save) plus `EMAIL_ENABLED`. When SMTP is configured the footer link opens a modal contact form (`tracker/templates/tracker/_contact.html`, a reusable partial `{% include %}`d by both pages, styled with shared CSS vars, square-cornered); otherwise it's a plain `mailto:`. The form POSTs `{name,email,message,website}` to `contact_api` (`POST /api/contact/`, **public, `@csrf_exempt`** because the landing page is per-visitor cached so an embedded token would mismatch, and a forged submit only mails the admin), which `send_contact_email`s to `contact_email` from `DEFAULT_FROM_EMAIL` with the sender as **Reply-To**. `website` is a spam honeypot (a filled value returns ok without sending). Blank `contact_email` hides the link entirely. Config only ⇒ **excluded from backups**, no `meta.version` bump. **New `SiteConfig` field ⇒ build + migrate.**
