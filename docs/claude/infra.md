# Infrastructure and runtime

_Read when: DB/cache behaviour, gunicorn, schedulers/threads, indexes, compression, outbound URL rules._

**Database:** SQLite (dev); PostgreSQL + PostGIS when `DATABASE_URL` is set. Code checks `HAS_POSTGIS` at runtime and falls back gracefully.

**Caching:** Redis when `REDIS_URL` is set, in-memory otherwise. `_bust_user_cache()` increments `cache_gen:{user_id}`, invalidating all cached API responses for that user.

**Local and LAN endpoints (`ALLOW_PRIVATE_OUTBOUND`).** Every URL a user or admin configures (AI base URL, OSRM, S3 endpoint, Overpass, Zepp host) goes through `net_utils.validate_outbound_url` when it is saved and again just before each request. It refuses private, loopback, link-local, reserved and **CGNAT/Tailscale (`100.64.0.0/10`)** addresses, and plain `http://`, unless `ALLOW_PRIVATE_OUTBOUND` is true. Redirects are never followed: `requests` call sites pass `allow_redirects=False`, and urllib ones (Zepp, Overpass) go through `net_utils.urlopen_no_redirect`, which turns a 3xx into an HTTPError naming the target. Overpass treats a refused redirect as mirror-down and fails over; a refused address is `unreachable`. That is the switch for a local Ollama / LM Studio. It was read in `settings.py` but not listed in `docker-compose.yml`, which names its environment variables explicitly, so setting it in `.env` never reached the container. Both compose files now pass it through (default `false`), and `.env.example` documents it. The `web` service also maps **`host.docker.internal` → `host-gateway`**, because `http://localhost` inside the container is the container itself; a model on the host is `http://host.docker.internal:<port>/v1`. Keep it off on an instance where other people have accounts: it lets any of them make the server fetch internal addresses. **Compose change ⇒ `up -d` (no rebuild needed).**

**Response compression:** `GZipMiddleware` (first after SecurityMiddleware) gzips all dynamic responses. WhiteNoise handles its own pre-compressed statics, so no double-compression occurs.


**HSTS is three opt-ins.** `HSTS_SECONDS` turns it on; `HSTS_INCLUDE_SUBDOMAINS` and `HSTS_PRELOAD` are separate env vars (default off), since preload is close to irreversible and once followed automatically from any non-zero `HSTS_SECONDS`.

**`settings.py` fails closed.** `DEBUG` defaults **False** (which is also what makes the custom error pages reachable) and `SECRET_KEY` has **no production fallback** — it raises `ImproperlyConfigured` at boot rather than silently running on a literal that ships in a public Docker image. A dev placeholder is still used when `DEBUG` is on.

**Postgres is published on loopback only** (`127.0.0.1:5433:5432` in `docker-compose.yml.example`). The app uses `db:5432` on the compose network; the host port is for psql/SSH tunnels. Docker inserts its own iptables rules ahead of ufw, so a bare `5433:5432` exposed the database to the internet regardless of the host firewall.

**`/healthz/`** (`views.healthz`, public) is a cheap liveness probe — one DB round-trip, one cache round-trip, 503 on failure — for the `web` healthcheck in `docker-compose.yml.example`, which also now waits on `db`'s `condition: service_healthy` instead of racing Postgres. It is excluded from `RequestLoggingMiddleware` (one hit per 30s would dominate the admin panel's top-paths) and from `robots.txt`.

**gunicorn: `--max-requests` must stay high, and `--preload` must never be added.** All background work runs in daemon threads started from `apps.ready()`, so recycling a worker kills an in-flight geocode / import / POI match / visit run / backup export — and job recovery only fires when someone polls that job's status, so unattended runs simply died. It was `500`, which a tracking phone plus a status poll reaches in minutes; it is now `10000`. The worker class is `gthread` with 8 threads: with the default sync worker the whole app had **3 concurrent requests**, and one unauthenticated 40 MB APK stream took a third of it. With `--preload`, `apps.ready()` would run in the master pre-fork, threads would not survive `fork()`, and each module's `_scheduler_thread` guard would see a non-`None` object in the children and skip starting them — **every background job would silently stop**.

**Persistent DB connections are health-checked** (`CONN_HEALTH_CHECKS = True` next to `conn_max_age=600` in `settings.py`). Each gunicorn thread keeps its own connection for up to 10 minutes, and when Postgres restarts or drops a backend that socket is dead on the Django side too — without the check, the next request on every one of the 24 threads failed with `InterfaceError: connection already closed` before Django noticed and reconnected. The check costs one `SELECT 1` on the first query of a request that reuses a connection.

**One-off background threads must be started with `scheduler_utils.db_thread`**, never a bare `threading.Thread`. With `conn_max_age` set, the `close_old_connections()` such jobs call on the way out closes nothing (a connection opened seconds ago isn't old), so the connection outlived the thread until the garbage collector freed it. `ensure_family_geofence_check` starts one per location push, and the leftovers exhausted Postgres's `max_connections` ("sorry, too many clients already") several times a day. `db_thread` wraps the target in `connections.close_all()`. The long-lived scheduler loops keep a bare `Thread` on purpose — one connection each for their whole life is the point.

**A scheduler thread must wait for the app registry before its first query.** `apps.ready()` runs *during* `apps.populate()`, so a loop whose first act is a query races the tail of startup. The models are already imported by that phase, so the query succeeds — but `apps.ready` is still False and Django emits `RuntimeWarning: Accessing the database during app initialization is discouraged` (added in **Django 5.0**, so this long predates the 6.1 upgrade) once per such thread on every boot. The warning is the harmless part; the cost is that a query raising there is swallowed by the loop's own `except`, so a scheduler can silently skip its **first** sweep and not retry until the next one — up to 6 hours later for the slowest. `tracker/scheduler_utils.wait_for_app_registry()` blocks on the flag itself rather than sleeping a fixed interval, so it costs milliseconds and leaves each loop's cadence alone. It is called by the five loops that query immediately (`backup`, `stats`, `summary_email`, `alert`, `family`) and deliberately **not** by `mobile_release_tasks`, which touches no DB. **Call it from inside the thread, never from `start_*`** — from the starter it would block `ready()` itself, which is the very thing that hasn't finished, and deadlock startup. A new scheduler that queries on its first pass needs the same two lines.

**Spatial queries must use the geography operators.** `Location.location` is a `PointField(geography=True)` with a **geography** GiST index, so `__distance_lte` (`ST_Distance`) and `__within` (`ST_Within`) are **not** index-accelerated and a `::geometry` cast in a WHERE clause makes the index unusable. Use **`__dwithin`** (`_find_nearby_locations`, 8 call sites — the yearly overview alone was running ~20 full-history spheroid scans per request), **`__bboverlaps`** (`_locations_api_inner`), and geography operands in `vector_tile`'s WHERE. `vector_tile` is the most-requested endpoint in the app and `/api/tiles/` is excluded from access logging, so its full-table scans never showed up in the admin panel.

**Two `Location` indexes** (migration `0083`): `tracker_loc_dev_ts_idx` is the **ASC companion** to `tracker_loc_device__idx` — a btree on `('device', '-timestamp')` reads as `(device ASC, ts DESC)` or `(device DESC, ts ASC)`, neither of which serves the `(device ASC, ts ASC)` that `track_api`, `trip_lines_api`, `_compute_distance_from_qs`, `_flag_suspicious_locations` and `_journal_day_track` all order by (`road_download_tasks` documents this trap and loops per device to dodge it; the views never did). `tracker_loc_unproc_idx` is **partial** on `processed_for_visits=False`, which had no index at all — each 5000-row visit chunk re-walked the history from the oldest end, O(n²) across a run.
