# Web UI: design system, appearance, shared components

_Read when: Templates, CSS, appearance layers, RoamlyForms/Dialog/Toast/Intro, settings layout, landing/SEO._

**Settings information architecture.** `/settings/` is one server-rendered template with seven client-side pages selected by URL hash: Account & Security, Appearance, Sharing, Maps, Email & Notifications, Data & Tracking, and API. The tab switcher groups the existing cards without changing their forms or API endpoints, within the app's standard 1150px content width. New settings cards must be added to the appropriate `pages` entry in `settings.html` so they do not fall into the Data & Tracking fallback unintentionally. The header is just the `Settings` title and the search field (no page-lead subheader); each page's own title and description render in `#settings-page-heading`.

**Settings search.** The field beside the title (`#settings-search`, focused by `/` when not typing in a field or with a dialog open) filters the cards of **every page at once**. Each `.settings-grid > .card` gets a lowercase, accent-folded text index (header, labels, help text, button text, `<option>` text, `placeholder`/`aria-label`/`title`/`data-tooltip`, plus the card's page label and a small per-card `keywords` map in the JS for words a card doesn't literally say, like `2fa` or `dark mode`). The index is rebuilt each time a search starts, so JS-rendered content (Appearance chips) is included; elements that are `hidden`, `display:none` inline or `aria-hidden` are skipped, as are the `per-account` header badges, and a card with `data-search-shallow` (the Appearance Preview, whose body is mock data) indexes only its header and direct `<p>`s. All space-separated terms must match. Matching cards are only un-hidden and grouped by page with CSS `order` (one `.settings-search-group` divider per page, with an "Open page" link); cards are never moved or re-rendered, so their controls work in place. The only DOM change inside a card is the header's title text node, swapped for a `<span>` with `<mark class="settings-search-mark">` and restored afterwards. `#settings-page-heading` shows the result count or a "No settings match" empty state. The × button, Esc, a tab click or a hash change ends the search and restores the current page exactly (the hash is never changed while searching). Admin-only content that the template doesn't render for the user is not in the DOM, so it can't be indexed.


**Design system (Field Journal, dark-first).** The web UI uses a cartographic-editorial system defined by CSS custom properties in `base.html`'s `:root` (dark, default) and `[data-theme="light"]` (paper). Palette: warm-ink backgrounds, trail-blaze orange `--primary` (#e8763d), and an earthy categorical set exposed through the **legacy clay-* token names** (`--clay-mint`=moss, `--clay-coral`=rust, `--clay-amber`=ochre, `--clay-lavender`=mauve, `--clay-sky`=map-blue) — the names were kept so all 18 base-extending templates restyle centrally; only values changed. Type: **Fraunces** (`--font-display`, serif), **IBM Plex Sans** (`--font-body`), **IBM Plex Mono** (`--font-mono`, used for all numerals/coordinates/micro-labels). Flat plates with 1px borders and hairline rules — the `--clay-shadow*` tokens now hold subtle/flat values (no puffy shadows), radii are 5–14px, and a faint topographic-contour SVG data-URI on `body::before` replaces the old gradient blobs. Inline links use `--link`/`--link-hover` (a lightened map-blue in dark, a deep one in light); before those existed nothing set a link colour and links fell back to the browser's near-invisible `#0000ee`. No `text-transform: lowercase` (removed globally), no glass blur, no gradient text/buttons. That removal was CSS-only — several `.page-header`/`.page-toolbar` `<h1>` titles (Health, Activities, Search, Visits, Statistics, Adventures, Places, Location data, Ask, Diagnostics and its three other tab panes) still carried literal lowercase copy left over from the old convention, inconsistent with `Journals`/`Settings`/`Admin Panel`; capitalized to match. **The six standalone pages** (`landing`, `login`, `signup`, `docs`, `privacy`, `terms`) don't extend `base.html`, so each carries its own copy of the token block + `@font-face` and is dark-only (no theme toggle). Theme switches via `roamly_theme` localStorage (default `dark`) → `data-theme`, read in `base.html` and set in `settings.html`. **Map JS accents** (markers/lines/device+member track palettes) are hardcoded to the new hexes; the **speed-gradient (blue→green→amber→red) and heatmap density ramps are functional encodings and deliberately left unchanged** in `map.html`/`trips.html`/`adventures.html`/`trip_public.html`.

**Appearance (Settings → Appearance; registry `tracker/appearance.py`).** The default look is Field Journal (its CSS untouched) with the **Squircle** shape: `PRESETS[0]` has `shape='squircle'`, so a fresh account or browser gets `data-shape="squircle"` and `facets.css`. Appearances saved before that switch (in `UserProfile.appearance` or a browser's `roamly_appearance`) keep the square `field` shape they stored; Shape → Field is still there for anyone who wants it. The Android app draws the same corners (`ui/theme/SquircleShape.kt`, see mobile-app.md). On top of it, a look is a set of **independent facets**, each its own layer under `tracker/static/tracker/styles/`, so they can be mixed freely:

| Facet | File(s) | Scope | Notes |
|---|---|---|---|
| palette | `palettes/<id>.css` | `html[data-palette]` | colour tokens only (dark + light) |
| components | `components/<id>.css` (+ `.js`) | `html[data-style]` | how cards, buttons, nav, tables, popovers, the map sidebar are drawn |
| shape | `facets.css` | `html[data-shape]` | `--r-1..4`, `--r-pill`, `--rk`, `corner-shape: squircle` |
| type | `facets.css` | `html[data-type]` | font tokens only |
| background | `backgrounds/<id>.css` (+ `.js`) | `html[data-bg]` | what sits behind the page |
| icons | `static/tracker/icons.js` (not a facet) | `window.RoamlyIcons.svg(name, size)` | ~70 hand-drawn 24×24 `currentColor` line icons for pages that would otherwise reach for emoji (Achievements, Health). Add a glyph to the `P` map; unknown names draw a medal |
| extras | `extras.css` / `extras.js` | `html[data-fx~=id]` | 30 small behaviours, one module each |
| size, motion | `facets.css` | `html[data-size]`, `html[data-motion]` | comfort settings; presets never change them |
| layout | `layouts/<id>.css` + `.js`, `templates/tracker/layouts/<id>/` | `html[data-layout]` | the page frame (beta): **not part of a look**, never in a preset; see *UI layouts* below |

The twelve **presets** (Field Journal plus Lantern, Transit, Jelly, Riso, Postmark, Broadsheet, Blueprint, Basecamp, Pebble, Tidepool, Bento) are just named facet sets in `appearance.PRESETS`; everything is mixable afterwards. `appearance.sanitize()` is the single validator (unknown values fall back, extras de-dupe, one extra per exclusive group: `title`, `numbers`, `navmark`, `entrance`, `press`), mirrored client-side by `normalize()` in the loader.

**The token contract is what makes mixing work.** Components and backgrounds use palette tokens only: the base set plus `--surface-0` (deepest chrome), `--paper`/`--paper-ink` (a contrast surface, e.g. Lantern's index cards), `--on-primary` (ink on the primary). `facets.css` supplies fallbacks for Field's palette, which predates them. Each components file opens with a block of **derived variables** (`--ink-pink: var(--primary)`, `--amber-hi: color-mix(…)`, Bento's tile fills as `color-mix` of the five data colours, …), so the same component CSS repaints itself under any palette. Literal `#000`/`#fff` and black/white shadows are deliberate constants. **Radii in components are role tokens** (`--r-1` tags, `--r-2` controls, `--r-3` panels, `--r-4` dialogs, `--r-pill`), never px, so the shape facet reaches them. `test_style_layer.py` checks every registered file exists and is scoped to its attribute, and every extra has a module.

**Pages follow shape too, which is the deep part.** Page templates wrote about 250 `border-radius: 0` (Field's square plates) and 36 literal radii. They are now `var(--r-auto, 0)` and `calc(Npx * var(--rk, 1))`: identical in Field (the vars are unset), driven by the shape facet otherwise. `facets.css` has a **zero-specificity role layer** (`:where(…)`) that sets `--r-auto` and a radius on every panel (`.card`, `[class*="panel"]`, `.sidebar-content`, menus, dialogs…), control (buttons, inputs, `[class*="btn"]`, tabs) and tag (badges, chips), including the many elements that declare no radius at all. Zero specificity means any deliberate radius (circles, `50%`) still wins. Each components file also ends with a **page chrome** block giving the map sidebar, replay bar, context menu, legend and their buttons that look's surfaces. **A new page needs nothing:** it picks up palette tokens, the role layer and fonts automatically. Write new radii as role tokens or `var(--r-auto, 0)`, not raw px.

**Loader: `_style_layer.html`** (in `base.html`'s head). The registry and the account's saved appearance arrive via `json_script` (`APPEARANCE_REGISTRY`, built once per process in `context_processors._appearance_registry`, and `APPEARANCE`). Precedence: `?rly_preset=` / `?rly_style=` (shareable preview), then the account (`UserProfile.appearance`, migration `0115`, a JSONField, so it follows you across devices), then `localStorage.roamly_appearance` (signed-out pages; legacy `roamly_style` is read once). It sets one attribute per non-default facet and `document.write`s only those layers' files: parser-inserted, render-blocking, no flash. **Only a Field Journal look with the square `field` shape sets nothing and loads nothing; the default (squircle) sets `data-shape` and loads `facets.css`.** `window.RoamlyStyle` exposes `registry`, `current`, `preset`, `normalize`, `set(app)` (POST `/api/profile/appearance/` then reload, keeping hash and scroll; it must `reload()` when only the hash would change) and `applyPreset(id)`. Alt+Shift+S cycles presets. `reducedMotion()` is true for the Calm motion setting or the OS preference, and every extra and background honours it. The **contrast guard** re-inks white-on-primary controls when `--on-primary` is dark (light primaries: Transit yellow, Basecamp amber, Blueprint marker…). `GET/POST /api/profile/appearance/` (`profile_appearance_api`, web-only, CSRF-checked) sanitizes before saving; `{"reset": true}` clears it. Config ⇒ **excluded from backups**. `/styles/` redirects to `/settings/#appearance`, which holds Presets, Mix and Match (theme, palette, components, shape, type, background, extras, size, motion) and Preview (the old Style lab's mock-data component showcase).

**Constraints every layer keeps:** the navbar stays sticky at the top with total height equal to `--nav-h` (map, ask, editor and journals size from it). The one exception is the **floating bars** (Jelly, Pebble, Tidepool components): on the main map page (`&:has(#map-container)`) the bar goes `position: fixed` over the map, the map takes the full viewport height, and `.map-sidebar`/`.map-top-center` move down to `calc(var(--nav-h) + 2px)`; `--nav-h` keeps its value so anything sizing from it still knows the bar's footprint. A new floating-bar components set needs the same block. no `transform`/`translate`/`filter`/`will-change` on `.card` at rest or on hover (it traps `position: fixed` children; Riso's tilt and Postmark's masks are `:has()`-guarded to cards that can't host overlays); bottom-nav labels keep base sizing; backgrounds sit at `z-index: -1`; the speed-gradient and heatmap ramps are untouched. New static files ⇒ `collectstatic` (runs on container start); template/model change ⇒ `up -d --build`.

**Custom form controls (`RoamlyForms`).** `base.html` ships a global framework-free progressive-enhancement layer (one IIFE + `.rly-*` CSS, both inline). The native element stays in the DOM as source of truth (hidden via `.rly-hidden-native`); a flat button trigger + `<body>`-attached fixed-position popup render the custom UI, dispatching real `input`+`change` events on selection. Programmatic `el.value = x` / `el.selectedIndex = i` are intercepted via `Object.defineProperty` to keep the visible label in sync. Custom `<select>` rebuilt from live `<option>`s on each open (keyboard: ↑/↓/Enter/Esc/type-to-open); date picker is Monday-first with `min`/`max`, today/clear, and month/year grid jump. A `MutationObserver` re-runs `RoamlyForms.enhance()` for controls injected later. Opt out: `class="rly-native"`. `<select multiple>` and `<input type="datetime-local">` left native. Pure template change — no rebuild/migration.

**`RoamlyDialog` — alert()/confirm() replacement.** `base.html` ships a global themed dialog (one IIFE + `.rly-dialog-*` CSS, both inline, same flat-plate/square-corner language as `RoamlyForms`/`_contact.html`) so no page shows a native browser popup. `window.roamlyAlert(message, {title})` and `window.roamlyConfirm(message, {title, danger, confirmText, cancelText})` both return Promises (`confirm` resolves `true`/`false`) — call sites `await` them, same shape as native `confirm()` but async, so the surrounding function needs `async`. A single lazily-created overlay is reused; opening a second dialog while one is open resolves the first as cancelled rather than stacking. Escape resolves false/undefined, Enter resolves true/undefined, backdrop click cancels. `danger: true` swaps the confirm button to `--danger` red — used for anything destructive (delete/remove/permanently). Every template that used `window.alert`/`window.confirm` (adventures, adventure_edit, adventure_plan, adventure_public, admin_panel, data_table, diagnostics, editor, journals, map, places, settings) now calls these instead. Pure template change — no rebuild/migration.

**`RoamlyToast` — non-blocking success/error confirmation.** `base.html` ships a global toast (one IIFE + `.rly-toast-*` CSS, same flat-plate language as `RoamlyDialog`), for the many small confirmations that don't warrant a blocking modal. `window.roamlyToast(message, {type: 'success'|'error', duration})` returns a `dismiss()` function; `duration: 0` disables auto-dismiss (default 3200ms success / 5000ms error). Stacks bottom-right, dismissible by the × or auto-timeout. Most per-page "saved ✓" / "copied" inline-text feedback is left as-is — it's debounced-autosave feedback next to the field being saved, which is better UX right there than in a corner toast — `roamlyToast` is for actions with no natural inline anchor (e.g. the public adventure page's copy-link, which previously misused a blocking `roamlyAlert` for this).

**Flash-on-load convention.** A redirect can carry `?flash=<key>` (e.g. `?flash=joined`, `?flash=welcome`) and `base.html` shows the matching canned `roamlyToast` once on load, then strips the param via `history.replaceState` so a refresh doesn't re-show it. Used by `trip_join_view` (only on an actually-new `AdventureMember`, not a revisit of an old invite link) and both signup-completion paths in `signup_view`/`verify_view` (only for `purpose == 'signup'`, never a returning user's new-device login check). New keys go in `base.html`'s `FLASH_MESSAGES` map.

**`RoamlyIntro` — first-run welcome tour.** A guided, page-by-page walkthrough of the app's main sections (Map, Adventures, Journals, Places, Search, Ask when enabled, Stats, Visits, Settings), shown automatically once to a genuinely new signup and replayable anytime after. Built the same way as `RoamlyForms`/`RoamlyDialog`/`RoamlyToast` — one self-contained IIFE + `.rly-intro-*` CSS, both inline in `base.html`, no external tour library. Unlike those components it has no single overlay to keep mounted: the pages it explains are separate Django views, so the tour spans real full-page navigations rather than one modal sequence. A fixed bottom bar (`.rly-intro-bar`, docked above `--bottom-nav-height`) shows the current step's title + one-paragraph copy and a "Skip intro" control, visible and clickable on every step; the **"Next" button is a separate fixed-position element outside the bar's flow** (`.rly-intro-next`, pinned to the same `right`/`bottom` coordinates regardless of page) so it never moves even when a step's copy wraps to a different number of lines. Clicking Next writes the next step index to `localStorage` and navigates (`window.location.href`) to that step's URL; the next page load re-reads the state and re-renders the matching step.

Two-tier persistence, deliberately split by durability: **`UserProfile.intro_seen`** (migration `0065`, `BooleanField(default=True)`) is the durable, server-side, cross-device "has this account ever had the tour auto-triggered" flag — `default=True` backfills every pre-existing profile so a tour added later never retroactively interrupts anyone, and `signup_view` explicitly passes `intro_seen=False` when creating a brand-new profile so only that signup gets the automatic trigger. The **`roamly_intro_active`/`roamly_intro_step`** localStorage keys (see User-facing preferences below) hold the ephemeral in-progress state — whether a tour is currently running and which step — since that's per-browser navigation state a server round-trip on every page load would be wasteful for, not a durable account preference. The moment the tour auto-starts, `base.html` fires a background `POST /api/profile/intro-seen/` (`profile_intro_seen_api`) to flip the server flag immediately — so an abandoned tour (tab closed mid-walkthrough) still never re-triggers on a later visit, matching "must only trigger automatically once" even though the localStorage progress itself could otherwise be cleared or lost.

Per-request tour data (step list + `INTRO_PENDING`, the server flag's negation) is rendered into `window.__RLY_INTRO__` by `base.html` itself, guarded by `{% if user.is_authenticated and not standalone %}` (so it's absent on `editor`/`adventure_public`, the only two `standalone: True` pages, and on the anonymous standalone templates that don't extend `base.html` at all) — `context_processors.custom_js_snippet` exposes `INTRO_PENDING` alongside the other per-user flags. `window.RoamlyIntro.start()` (used by Settings → General Preferences → **"Replay intro"**) resets the localStorage state and navigates to the first step regardless of `intro_seen` — replay is purely client-side and never touches the server flag, so it can be repeated indefinitely. If the tour is active but the user navigates to a page with no matching step (e.g. Diagnostics), the bar simply doesn't render that load; state is untouched, so landing back on a tour page resumes it. **New `UserProfile` field ⇒ build + migrate.**

**Global JS error safety net + offline banner.** `base.html` also registers `window.onerror`/`unhandledrejection` listeners that surface a generic `roamlyToast('Something went wrong on this page.', {type:'error'})`, capped to one per page load — it doesn't fix root causes, it just stops a page failure from being silently invisible (a frozen skeleton with no indication anything broke). A separate `navigator.onLine`/`online`/`offline` listener pair drives a persistent top `.rly-banner` ("You're offline — showing cached data where available"), sitting below the sticky navbar on pages that have one (`body:has(.navbar) .rly-banner`). Pairs with the service worker's existing cache-fallback behavior, which previously had no accompanying UI explanation.

**Custom error pages.** `roamly/urls.py` registers `handler400/403/404/500` pointing at thin views in `views.py` (`error_400`/`error_403`/`error_404`/`error_500`) that all render a shared standalone `tracker/_error.html` (own copy of the token block, no nav chrome, no DB/session dependency — the 500 page in particular has to render when something is actually broken). These only take effect in the deployed environment when `DEBUG=False`; `DEBUG` defaults to False, so a deploy sees them unless it turns `DEBUG` on. **`_error_page` renders with `render_to_string` and no request**, deliberately: passing the request runs the context processors, which read the session and profile from the database, so a 500 *caused* by the database raised again inside its own error page and the visitor got a bare gunicorn error instead.

**Breadcrumbs.** `tracker/_breadcrumb.html` (`{% include %}`d with a `crumbs` list of `{label, url}` dicts, last entry has no `url`) is wired into `adventure_edit.html`, the one genuinely nested page that previously had only a bare back-arrow overlaid on its cover image with no visible trail. `adventure_plan.html` already has an equivalent back-link + trip-title bar and doesn't need it; `adventure_public.html` renders `standalone: True` (deliberately chrome-free for anonymous/shared visitors) so breadcrumbs there would fight that design intent.

**Skeleton loaders.** `base.html` ships a shared shimmer primitive (inline CSS): `.skeleton` gives any block the animated placeholder tint (a `::after` gradient sweep over `--bg-elevated`; light theme brightens the sheen via `--skeleton-sheen`, reduced-motion swaps the sweep for a gentle opacity pulse). Shape helpers: `.skel-line`(`.sm`/`.lg`), `.skel-circle`, `.skel-statval` (inline em-sized bar for big numeric stat tiles, scales with the element's font-size), `.skel-card`. Applied on initial page-load content across the data-driven pages — `stats` (stat tiles, timeline, states, transport bars), `places` (card grid + detail-modal stat grid), `visits` (table rows, all three tabs), `adventures`/`pals` (list cards), `journals` (stat chips + recent entries), `data_table` (table rows). User-triggered actions (search, load-more, recompute, diagnostics analysis) deliberately keep the `.spinner` — skeletons are for predictable-shape content that loads on page load, not one-off actions. Containers carry `aria-busy="true"`, cleared when data lands. Pure template change — no rebuild/migration.

**Landing page performance:** Hero stats read from `site_stats` cache key (1h TTL). Anonymous responses get `Cache-Control: public, max-age=300, stale-while-revalidate=86400` + `Vary: Cookie, Accept-Encoding`. Fonts are self-hosted (`tracker/static/tracker/fonts/{fraunces-latin-var,plex-sans-latin-{400,500,600,700},plex-mono-latin-{400,600}}.woff2`), the two LCP faces (`plex-sans-latin-400`, `fraunces-latin-var`) `<link rel="preload" as="font" crossorigin>`-ed, all served by WhiteNoise with 1-year immutable cache; no Google Fonts CDN anywhere (zero third-party). **New font files need `collectstatic` or `{% static %}` 500s on a missing manifest entry.** All CSS is inline and minified — edit it knowing it's a single line, re-minify after heavy edits. Heading order is strictly h1→h2→h3.

**SEO (`robots.txt` + `sitemap.xml`).** `robots_txt` (`/robots.txt`) allows the public marketing/legal pages, `Disallow`s the login-gated app + `/api/`, and points to `Sitemap: <site>/sitemap.xml`. `sitemap_xml` (`/sitemap.xml`, `views.sitemap_xml`) emits a plain `application/xml` `<urlset>` (built by hand, no `django.contrib.sitemaps`): the four public standalone pages (`/`, `/docs/`, `/privacy/`, `/terms/`) plus every published adventure (`Adventure.public_slug` non-null/non-empty → `/adventure/<slug>/`, `lastmod` from `updated_at`). Everything else stays out to match `robots.txt`'s Disallow list. Both build absolute URLs from `request.build_absolute_uri`. Python change ⇒ restart `web`.

**Appearance fixes (Field Journal + squircle).** Underline indicators on `.navbar-nav-toggle` and `.settings-nav button` are `::after` bars, not `border-bottom` (a border follows the shape facet's radius and curls up the sides). `.pill-tabs .tab-btn` has `border-radius: 0` because the group clips itself; per-tab radii left notches and curved separators (Visits tabs). The **jelly background** (`backgrounds/jelly.js`) renders at CSS-pixel resolution (`scale` 1, canvas ≤ 2000px wide, stepping down 0.6 → 0.45 → 0.32 only when frames run long) and runs a small JS physics step: the pointer shoves blobs and passes on its velocity, a weak spring pulls each back to its orbit, walls bounce them; positions go to the shader as `uC[6]`.

**Loading spinner = the Roamly mark.** `.spinner` (`base.html`) renders the logo from two inline-SVG CSS masks tinted by `currentColor`/`--primary`: `::before` is the dashed orbit ring + arrowhead (rotates, `spin`), `::after` is the pin (bobs, `spin-pin`). Per-style spinner skins in `styles/components/*.css` are neutralised with `!important` on border/background/mask/animation so every style shows the logo; size it with `width`/`height` as before. The map-loading overlay in `adventure_edit.html` uses the same `.spinner`. Template-only change.

**Navbar details.** Logout lives only in the account dropdown (a separate `.navbar-logout-mobile` corner button used to show next to it — `.btn` out-ranked its `display:none` — and was removed). Active-state indicators for the top nav (underline, brackets, chips in each components file, the Riso marker extra) are scoped to **top-level links** (`.navbar-nav > li > a.active`), so the current page inside the Data dropdown is marked only by the dropdown's own `.nav-dropdown-menu a.active` tint, never an underline. The version footer is `{% block version_footer %}` in `base.html`; `map.html` overrides it empty so the full-viewport map page can't scroll to reveal it. **Page subheaders** (`.page-lead` one-liners under the `<h1>`) were removed from most pages; Diagnostics keeps the Subway gaps and Trash explanations because they're instructions, not decoration. Don't add new ones.

**UI layouts (beta; Settings → Appearance → Layout; `tracker/layouts.py`).** Classic (today's navbar UI, loads nothing) plus three alternative arrangements: **Atlas** (map-first: icon rail, Journals/Places/Visits slide over the map as iframe panels), **Chronicle** (time-first: `/timeline/` day feed beside a map) and **Hearth** (`/home/` dashboard of cards, left sidebar). A layout changes markup, not just CSS, so the **server decides it**: `layouts.request_layout(request)` reads `?rly_layout=<id>` (a one-page-load preview), then `UserProfile.appearance['layout']` (validated by `appearance.sanitize`, default `classic`), and the context processor exposes `LAYOUT`, `LAYOUT_SHELL` and `EMBED`. The client only mirrors it: `_style_layer.html` sets `window.__RLY_LAYOUT__`, `html[data-layout]`, loads `styles/layouts/<id>.css|js` (any non-classic layout also loads `facets.css`, so palette fallbacks and role radii exist) and forces `app.layout` to the server value so a stale localStorage copy can never disagree with the rendered markup. `RoamlyStyle.setLayout(id)` saves and reloads. **Layout is not a look:** presets never carry it, `matching_preset` ignores it, `applyPreset`/Reset keep it, and `profile_appearance_api` keeps the stored layout when a POST doesn't name one.

*Switching.* `base.html` renders `{% include LAYOUT_SHELL %}` (`tracker/layouts/<id>/shell.html`) **instead of** the navbar and bottom nav, so a shell owns all navigation (desktop and phone) and sets its own `--nav-h` / `--bottom-nav-height` (base.html resets the latter to a 68px bar under 768px; a shell without a bottom bar must override it to `0px`). The year-ago chip and notification bell are shared partials (`_nav_yago.html`, `_nav_notif.html`); base.html's JS finds them by id. Page views call `layout_templates(request, page)` (map, stats, journals, places, adventures, health, visits), so a layout redesigns a page just by shipping `tracker/layouts/<id>/<page>.html`; anything it doesn't ship falls back to the classic template inside the new shell. `/home/` and `/timeline/` (`layout_views.py`) exist only for Hearth and Chronicle and redirect to the map under any other layout, so bookmarks never 404. Their data comes from `GET /api/layout/home/` (`layout_home.py`) and `GET /api/layout/timeline/` (`layout_timeline.py`).

*Embed mode.* `?embed=1` sets `standalone` (no shell, intro or version footer) and `SecurityHeadersMiddleware` relaxes framing for those responses only (`X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`); every other response is still `DENY`/`'none'`, and `frame-src` gains `'self'` for the Atlas panels' iframes.

*Rules for layout CSS/JS.* Every rule is scoped to `html[data-layout="<id>"]` (a test checks the file starts with it); own classes use the `lx-<xx>-` prefix; colours and radii come only from palette tokens and the `--r-*` role scale, so every palette, component skin, shape and background still mixes with every layout; chrome stays under z-index 9000 so RoamlyDialog/Toast sit above it; no transform/filter on ancestors of fixed children. **Classic must stay byte-for-byte equivalent**: `git diff main` on the six classic page templates must be empty, and `test_classic_keeps_the_navbar` guards the shell switch.


**Atlas** (`layouts/atlas/`, `styles/layouts/atlas.css|js`). Desktop has no top bar (`--nav-h: 0`): a 56px icon rail on the left (Map, Journals, Places, Visits, Adventures, Health, Stats, Search, Ask, a More menu, then year-ago/bell/account). Phone gets a bottom tab bar plus a More sheet. On `/map/`, Journals/Places/Visits don't navigate: `atlas.js` opens a panel (side panel 360–720px, resizable, or a three-snap bottom sheet on phones) holding an iframe of the page with `?embed=1`, pushes `?panel=<id>` so reload/back/deep links work, and swaps the iframe for another panel page. Inside the frame `atlas.js` sets `html.lx-embedded`, forwards Esc, and re-routes link clicks to the top window or to another panel; frames that load a page that can't be shown fall back to an "Open full page" notice (POST forms inside a panel don't work, so panel pages use `fetch`). `LxAtlas.open(id)` / `.close()` and `postMessage({rlyPanel:'close'})` control it; an open overlay carries `data-lx-esc` so Esc closes it before the panel. Redesigned pages: stats, health, adventures (full pages), journals, places (panel-capable). Primitives (`.lx-at-*`) are documented at the top of `atlas.css`.

**Chronicle** (`layouts/chronicle/`, `styles/layouts/chronicle.css|js`, `layout_timeline.py`). The combined "best of all" layout. **Left sidebar, no top bar**: 232px, collapsible to a 64px rail (`roamly_ch_side` `'1'` = rail, applied before first paint by an inline script at the top of `shell.html`, which also starts a 769-1100px window as the rail when nothing is stored; `html[data-ch-side="rail"]`). The brand mark and the collapse button sit at fixed coordinates in both widths (mark and button centred on x=32, button at y=56) so the button never moves. Top to bottom: brand (links to the timeline), collapse + visible **Search** field (`/` key opens it, or focuses `#search-input` on /search/; the Ask page keeps its own `/`), **Ask Roamly** when `AI_ASK_ENABLED`, Overview (`layout_home`), Timeline, Map, Journals, Places, Adventures, Trip (if featured), Health, Stats, a collapsible **More** group (Visits, Achievements, Flights, Raw data, Cell signal, Map editor; `roamly_ch_more` `'1'`/`'0'`, absent = open only while the current page is inside it; always shown in the rail), then the foot: year-ago chip, **Jump to day** (a real, visible `input[type=date].rly-native`, `[data-ch-jump]`; in the rail an invisible hit area over the icon that calls `showPicker()`), account menu (Settings, Appearance, Diagnostics, Admin, Log out) and the bell. **Layout contract**: `--lx-ch-side` (232px | 64px | 0px on phones), `--nav-h: 0px` on desktop *and* phone, `body { padding-left: var(--lx-ch-side) }`, all only while `#lx-ch-side` is in the page (`:has()`), so `?embed=1`/standalone pages keep base's values; fixed full-bleed things use `left: var(--lx-ch-side)` (offline banner and intro bar are patched in `chronicle.css`; Ask's `.ask-app`/`.ask-side`/`.ask-mappanel` too); never `100vw`. z-index: sidebar/dock 1000, menus 1100, sheet 8500-8600. **Phone (<=768px)**: no header; five-item dock (Timeline, Map, Journals, Places, More) + a More sheet that holds Search, Jump to day, the bell (the single `#notif` is moved between the sidebar foot and the sheet header by `chronicle.js`; its unread dot is mirrored on the dock's More item), Overview and everything else. **Year-ago chip**: `base.html` only wires it above 1280px (a `matchMedia('(max-width: 1280px)')` early return), so `shell.html`'s first script answers that one query for the phone breakpoint until `DOMContentLoaded`; the chip then shows in the sidebar at every desktop width and stays hidden on phones. `window.RoamlyChronicle` (`selectedDate`, `setDate`, `jumpTo`, `onDate`, `today`, `parse`, `format`, `collapse`, `isCollapsed`) shares the date; `jumpTo(iso)` selects a day on /timeline/ (listeners always fire) or navigates to `/timeline/?date=iso` elsewhere; /timeline/ reads `?d=` or `?date=` (normalised to `?d=`). Shared CSS helpers for page templates (documented in the `chronicle.css` header): the `.lx-ch-page`/`-title`/`-row`/`-chip`/`-seg`/`-btn` primitives, `.lx-ch-ai` (the one quiet AI button with a thin animated bottom glow; there was no earlier AI glow style in the product), `.lx-ch-timeline-spine` (+ `.lx-ch-day`, `-day-head`, `-day-num`, `-day-sub`, `-day-body`, `.lx-ch-spine-month`; scoped so the /timeline/ feed's own `.lx-ch-day*` rules are untouched), `.lx-ch-flat`, the opt-in `.lx-ch-flatten` wrapper (classic `.card`/`.stat-card`/`.table-wrap` inside it lose background, border, shadow and radius, keeping a hairline) and the `[data-ch-menu]` overflow menu (delegated, works on dynamic markup). `/timeline/` is a day feed (newest first, infinite scroll by `before` cursor, quiet days collapsed, a 24-month activity strip) beside a MapLibre map that follows the selected day. `GET /api/layout/timeline/?before=&limit=&year_strip=1` returns local-day cards (`distance_km`, `moving_seconds`, `places`, `transport`, `journal`, `health`, `flights`, `adventure`, `notes`) plus `next_before`/`activity`; its module docstring has the full shape. A response with no days but a non-null `next_before` means keep paging (one request scans at most 595 days).

**Hearth** (`layouts/hearth/`, `styles/layouts/hearth.css|js`, `layout_home.py`). A 232px sidebar (collapsible to a 64px rail, `--hearth-side`, `html[data-hearth-collapsed]`) and a phone drawer + tab bar; `/home/` is a card grid (Today, Recent outing, On this day, Stats & achievements, Health, Devices & family, quick note). `GET /api/layout/home/` returns one key per card in one response; any section can be `{error: true}` and the card shows Retry (`?only=a,b` refetches just those, uncached). Cached 60s per user, never when a section failed. Family data is stricter than `family_locations_api`: accepted viewers and members with sharing on only, no coordinates. Health has no sleep data in the models, so the card shows steps, distance, active kcal and the last workout. Primitives (`.lx-he-*`) are documented at the top of `hearth.css`.

**Layout page coverage.** Atlas, Chronicle and Hearth each ship their own `stats`, `health`, `journals`, `places` and `adventures` templates under `templates/tracker/layouts/<id>/` (page CSS inline under `html[data-layout="<id>"]`, classes `lx-<xx>-…`); `map` and `visits` use the classic templates inside each shell. Every page keeps the classic page's API calls and `roamly_*` prefs. Deep links added: Journals `?date=YYYY-MM-DD` (Chronicle, Hearth, Atlas), Timeline `?d=YYYY-MM-DD`. Known gaps: the adventures list API has no distance, so the layout pages estimate it from the ~200-point preview (shown as "~N km"); `place_update` doesn't refresh `places_json` for notes/notification edits, so `/api/places/` can show them stale until the nightly recompute.
