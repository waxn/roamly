Log retention

An hourly background job prunes old log rows. Daily aggregate rollups are kept forever (so long-range graphs survive), and low-volume events are kept long-term — only the high-volume per-request access log is pruned aggressively by default.

Custom JavaScript instance-wide

HTML injected verbatim just before </body> on every page — including the public landing, login & signup pages — for analytics snippets pasted exactly as the provider gives them, including <script> tags (GoatCounter, Plausible, Fathom, PostHog…). Leave empty to inject nothing.

Testing tip: many analytics tools (GoatCounter included) ignore visits from localhost/127.0.0.1 by default, so hits only show up once the instance is reached over its real domain. To confirm the snippet is live, open any page, choose “View Source”, and check it appears just before </body>.

Contact Address

Shown as a contact link in the footer of the landing and settings pages. When SMTP email is configured, that link opens a contact form that emails this address (replies go to the sender); otherwise it's a plain mailto: link. Leave empty to hide the contact link entirely.

Cloudflare Turnstile CAPTCHA

Optional bot-protection widget on the login and signup pages, on top of the existing per-IP rate limiting. Get a site key + secret key from the Cloudflare Turnstile dashboard (free). The mobile app never renders the widget, so it stays exempt regardless of this setting.

Road, subway and POI data are instance-wide reference tables shared by every user — no user owns them, so downloading and deleting them lives here rather than in each person's own Settings. The download area for each covers everyone's combined travel history, not just yours.

Overpass Connection

All three downloads below fetch their data from Overpass. Endpoints are tried in order, moving on to the next only when one can't be reached or is too slow to answer — so a single dead or overloaded mirror no longer fails a whole run. Reorder to change which is tried first, remove any you don't want, and add your own.

Road Data instance-wide

Fetch OpenStreetMap roads for the areas anyone on this instance has actually been, so snapping and the editor's road routing can run entirely on your own server with no external calls. Only drivable roads are stored, and only for the ~2km cells someone has points in. This is the largest table in the app — expect tens of MB for one region, more if people road-trip. Re-run after someone travels somewhere new, or leave auto-download on below.

Subway Data instance-wide

Fetch OpenStreetMap subway tracks and stations for the areas anyone on this instance has been, so Diagnostics → Subway Gaps can find underground rides GPS never recorded and fill them along the real line. Subway data is far smaller than road data. Re-run after someone rides the metro somewhere new, or leave auto-download on below.

POI Data instance-wide

Fetch named OpenStreetMap places (shops, cafés, parks, landmarks…) within 15km of every city anyone on this instance has visited, so points can show a Place name (via each user's own Match POIs job in Settings) and Search can find things by name. Re-run after someone visits a new city, or leave auto-download on below.
