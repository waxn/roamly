roamly docs

setup, api reference, and guides for self-hosted gps tracking — map, adventures, pals, visit analytics, and everything that runs on your server.

docker gpslogger api adventures pals help

introduction

roamly is a self-hosted location tracking platform. push gps from your phone, explore your history on a maplibre map, log adventures and pals trips, analyze where you've been, and keep every byte on hardware you control.

what you get

  • map — heatmap, speed-colored dots, path lines, time-range filters; postgis vector tiles or classic clustered mode
  • multi-device — separate api keys per device, per-device colors on the map
  • adventures — time-bounded outings with places, timeline blurbs, photos, milestones, public slug + optional pin
  • pals — group trips where each member contributes their own gps track on one shared map
  • visit analytics — dwell time per city/state/country, yearly period comparisons
  • stats & search — distance charts, location data table, place/date search
  • reverse geocoding — nominatim with spatial clustering (background job in settings)
  • import & export — csv, gpx, google takeout json, owntracks json, full backup restore
  • s3 backups — scheduled data + image backups to any s3-compatible storage
  • gpslogger & owntracks — or any client that can post json to /api/push/
  • pwa — installable; dark and light themes

tech stack

  • backend: django + python, gunicorn; background work in threads (geocoding, backups, poi download)
  • database: sqlite by default; postgresql + postgis when DATABASE_URL is set (enables vector tiles)
  • frontend: vanilla javascript, maplibre gl, canvas charts
  • deployment: docker compose

docker setup

roamly runs as a two-container docker compose stack — a postgis database and the django web app. everything is configured out of the box.

prerequisites

  • docker and docker compose
  • 2 gb ram minimum, 1 gb free disk
  • port 8001 available (and optionally 5433 for db access)

install & run

# clone the repo
git clone https://github.com/waxn/roamly.git
cd roamly

# start everything
docker compose up -d
that's it. roamly is now running at http://localhost:8001. migrations and static files are handled automatically on startup.

what gets started

serviceimageportdescription
db postgis/postgis:16-3.4 5433 → 5432 postgresql with postgis spatial extensions
web built from dockerfile 8001 → 8000 django app served by gunicorn (3 workers)

data persistence

data lives in bind-mount volumes that survive container rebuilds:

  • ./data/postgres/ — all database data
  • ./staticfiles/ — collected static assets

useful commands

# view logs
docker compose logs -f web

# stop everything
docker compose down

# rebuild after an update
docker compose down && docker compose up -d --build

# open a db shell
docker compose exec db psql -U roamly -d roamly

# back up the database
docker compose exec db pg_dump -U roamly roamly > backup.sql

# restore
docker compose exec -T db psql -U roamly roamly < backup.sql

first steps

after docker compose up -d, follow these steps to start tracking your first device.

1

create an account

open http://localhost:8001 and click get started. enter a username and password — no email required.

2

create an api key

go to settings → api keys → create api key. name it after your device (e.g., "pixel 9"). copy the 64-character key.

3

set up a tracking app

install gpslogger on android (or owntracks on ios/android) and point it at your server. see the gpslogger setup section for step-by-step instructions.

4

verify it's working

after gpslogger sends its first location, check the map page. if nothing appears, see troubleshooting.

5

run geocoding

go to settings → start geocoding to convert coordinates to city/country names. runs in the background.

roamly geocodes new locations automatically as they arrive. the background job is for bulk-processing imports or locations that missed geocoding.

configuration

roamly is configured via environment variables — set them in a .env file in the project root, or directly in your hosting platform (portainer, etc.). no hostnames are hardcoded.

environment variables

variabledescriptiondefault
DEBUG django debug mode. set to False in production. False
SECRET_KEY django secret key. change this in production. change-me-in-production
POSTGRES_PASSWORD database password. roamly_secret
ALLOWED_HOSTS comma-separated hostnames. set to your domain in production. localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS comma-separated urls with protocol. must include your https url. http://localhost
DATABASE_URL full db connection string. auto-configured in docker compose. postgis://roamly:...@db:5432/roamly

example .env

DEBUG=False
SECRET_KEY=your-random-secret-key-at-least-50-chars
POSTGRES_PASSWORD=a-strong-database-password

# comma-separated, no protocol
ALLOWED_HOSTS=roamly.yourdomain.com

# comma-separated, include protocol
CSRF_TRUSTED_ORIGINS=https://roamly.yourdomain.com
always change SECRET_KEY and POSTGRES_PASSWORD before exposing roamly to the internet.

generating a secret key

python3 -c "import secrets; print(secrets.token_urlsafe(64))"

gpslogger setup

gpslogger is a free, open-source android app for logging gps data to a custom url. it's lightweight, battery-friendly, and the recommended way to send locations to roamly.

install gpslogger

  • android: f-droid or google play

configuration

1

get your api key

settings → api keys → create api key. name it after your device (e.g., "pixel 9"). copy the key.

2

enable custom url logging

in gpslogger, tap the three-dot menu → logging details, then enable log to custom url.

3

configure the url

tap log to custom url to open its settings:

  • url: https://your-domain.com/api/push/
  • http method: post
  • http body:
{"api_key":"YOUR_KEY","device_id":"%SER","latitude":%LAT,"longitude":%LON,"altitude":%ALT,"speed":%SPD,"accuracy":%ACC,"battery":%BATT,"timestamp":"%TIME"}
  • http headers: Content-Type: application/json
4

set logging interval

go back, tap performance, and set your preferred interval (e.g., 60 seconds).

5

start logging

tap the start button. your points should appear on roamly's map within seconds.

the %SER placeholder sends the device's serial/id, which roamly uses as the device identifier. you can replace it with any fixed string if you prefer a custom device name.

gpslogger not working?

  • make sure the url ends with /api/push/ — trailing slash matters
  • verify Content-Type: application/json is set in http headers
  • check the api key in the json body has no extra spaces
  • confirm your server is reachable from your phone's network
  • check logs: docker compose logs -f web

owntracks (ios & android)

roamly is also fully compatible with owntracks — the recommended option for ios users.

  • ios: app store
  • android: google play or f-droid

in owntracks preferences, set mode to http and the url to:

https://your-domain.com/api/push/?api_key=YOUR_KEY

tap the publish button (↑) to send a test location.

sending locations

push locations from any app or script that can make http requests. the /api/push/ endpoint accepts json.

authentication

  1. authorization header: Authorization: Bearer YOUR_KEY
  2. url parameter: ?api_key=YOUR_KEY
  3. json body field: "api_key": "YOUR_KEY"

standard format

curl -X POST https://your-domain.com/api/push/ \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "my-phone",
    "latitude": 48.8566,
    "longitude": 2.3522,
    "timestamp": "2026-01-15T14:30:00Z",
    "altitude": 35.0,
    "accuracy": 5.0,
    "speed": 1.2,
    "battery": 85
  }'

field reference

fieldtyperequireddescription
device_idstringyesunique identifier for the device
latitudenumberyesdecimal degrees, -90 to 90
longitudenumberyesdecimal degrees, -180 to 180
timestampstring / numbernoiso 8601 or unix timestamp. defaults to now.
altitudenumbernometers
accuracynumbernogps accuracy in meters
speednumbernometers per second
batterynumberno0–100

owntracks format (compatibility)

roamly also accepts the native owntracks json format directly:

{
  "_type": "location",
  "tid": "ph",
  "lat": 48.8566,
  "lon": 2.3522,
  "tst": 1705325400,
  "alt": 35,
  "acc": 5,
  "vel": 4,
  "batt": 85
}

response

// success (200)
{ "status": "ok", "location_id": 12345, "device": "my-phone" }

// error (401)
{ "error": "Invalid or missing API key" }

python example

import requests, time

resp = requests.post(
    "https://your-domain.com/api/push/",
    json={
        "device_id": "python-script",
        "latitude": 51.5074,
        "longitude": -0.1278,
        "timestamp": int(time.time())
    },
    headers={"Authorization": "Bearer YOUR_KEY"}
)
print(resp.json())

adventures

adventures let you capture any outing — a 7-hour bike ride, a hiking day, a road trip, a vacation. they group location data by a precise start and end time for a specific device.

creating an adventure

1

go to adventures

click adventures in the navigation bar.

2

create adventure

fill in: name, device, start date & time, end date & time, optional description. time precision means you can log a morning run without including the afternoon commute.

3

view the adventure

click on an adventure to open a full-screen map. under 20k points: all dots shown immediately with a heatmap and trail line. over 20k: heatmap-first with progressive dot loading as you zoom.

adding places

places are named waypoints — trailheads, cafés, landmarks. roamly calculates time spent using haversine proximity.

  1. open an adventure → sidebar → places → click + add place
  2. click on the map to drop a pin
  3. set a radius in meters — gps points within the radius count as "at this place"
time calculation: roamly uses haversine to find which points fall within a place's radius, then sums gaps between consecutive in-radius points (gaps over 2 hours are skipped).

timeline & notes

each adventure has a sidebar with a notes area, a timeline of posts, and a milestones section.

  • notes: free-form text for the adventure; saved automatically.
  • timeline: post updates with optional photos and a pinned map location. useful for logging moments during the activity.
  • milestones: named events with an emoji and date — summit reached, border crossed, finish line.

sharing

adventures can be made public with a custom slug. optional access pin gates the public page — visitors enter the pin once per browser session. share link format: /adventure/your-slug/

pals

pals are multi-user group journeys — like adventures, but each member logs their own device. everyone's track appears on one map with a shared timeline, blurbs, and milestones.

creating a pal trip

1

open pals

click pals in the nav bar → + new pal.

2

invite members

add roamly users by username. each member pushes locations from their own api key and device.

3

share optionally

toggle public sharing for a read-only page at /pal/your-slug/ — same pattern as adventures.

profile photos show on the pal map and timeline. upload yours under settings → profile picture.

import & export

your data is yours — export anytime in open formats, import from other services.

export formats

  • csv — all locations as a spreadsheet. columns: device, lat, lng, altitude, accuracy, speed, battery, timestamp, city, state, country, country_code.
  • gpx 1.1 — compatible with google earth, qgis, garmin, most gps software.
  • json backup — everything: devices, locations, trips, places, api keys. use this to migrate servers or take a complete snapshot.

import formats

  • csv — flexible column detection (garmin, strava, gpslogger aliases). minimum: latitude, longitude, timestamp.
  • gpx — track points, route points, and waypoints from gpx 1.0 and 1.1.
  • json — google takeout {locations:[...]} or owntracks array format.
  • restore from backup — full json snapshot; duplicate locations are skipped automatically.

imports prompt you to pick or create a device name so all points land on the right track.

geocoding

reverse geocoding converts coordinates to city, state, and country names. roamly uses openstreetmap nominatim — free, no api key required.

how it works

  • real-time: new locations are geocoded immediately on arrival
  • background batch: for imports or missed geocoding, run the job from settings

spatial clustering

nominatim allows 1 request per second. to work around this, roamly groups nearby points into ~111m grid clusters and geocodes one representative per cluster, then applies the result to all points in it. 100k points in a few cities might need only a few thousand requests.

what gets stored per location

  • city — city, town, village, or municipality
  • state — state, province, or region
  • country — full country name
  • country_code — iso 3166-1 alpha-2 (e.g., us, de)
  • place_name — full nominatim display name

setup

1

create a bucket

create a bucket in your provider. note the name, endpoint url, and region.

2

get credentials

create an access key and secret key with read/write access to the bucket.

3

configure in roamly

settings → automatic backups → fill in endpoint url, bucket name, access key, secret key, path prefix, region.

4

test and schedule

click test connection, then choose a schedule: daily, weekly, or monthly.

backup format

backups are json files containing all your devices, locations, trips, places, and api keys:

{prefix}{username}/backup_{YYYY-MM-DD_HHmmss}.json
# e.g.: roamly-backups/alice/backup_2026-02-17_143022.json
the backup scheduler checks every 15 minutes whether a backup is due, so the exact run time varies by up to 15 minutes from the configured interval.

reverse proxy

for production, put roamly behind a reverse proxy for https and clean domain routing.

nginx

server {
    listen 80;
    server_name roamly.yourdomain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name roamly.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/roamly.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/roamly.yourdomain.com/privkey.pem;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

let's encrypt

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d roamly.yourdomain.com
update your .env when using a reverse proxy:
ALLOWED_HOSTS=roamly.yourdomain.com
CSRF_TRUSTED_ORIGINS=https://roamly.yourdomain.com

caddy (simpler)

caddy handles ssl automatically with zero configuration:

# Caddyfile
roamly.yourdomain.com {
    reverse_proxy localhost:8001
}

security

production checklist

  • set DEBUG=False
  • change SECRET_KEY to 50+ random characters
  • change POSTGRES_PASSWORD to something strong
  • set ALLOWED_HOSTS to your domain only
  • set CSRF_TRUSTED_ORIGINS to your https url
  • use https via nginx or caddy + let's encrypt
  • don't expose port 5433 to the internet

api key practices

  • create a separate key per device
  • deactivate keys you're not using
  • delete keys for retired devices
  • roamly tracks last-used time per key — audit occasionally

data deletion

from settings:

  • delete all locations — removes location data, keeps account and trips
  • delete account — permanently removes everything

updating

cd roamly
git pull
docker compose down && docker compose up -d --build

migrations run automatically on startup.

back up before updating:
docker compose exec db pg_dump -U roamly roamly > backup_$(date +%Y%m%d).sql

architecture

system overview

mobile device (gpslogger / owntracks / custom app / script)
    │
    │ POST /api/push/  (api key auth)
    ▼
roamly web server (django + gunicorn)
    ├── api endpoints (push, locations, trips, import/export)
    ├── web ui (maplibre gl, canvas charts, vanilla js)
    └── postgresql 16 + postgis 3.4
            ├── locations with point geometry (srid 4326)
            ├── vector tiles via st_asmvt (30s cache)
            └── spatial filtering with st_intersects

background threads
    ├── reverse geocoding (nominatim, spatial clustering)
    ├── s3 backup scheduler (checks every 15 min)
    └── auto-resume stale jobs on startup

data model

user (django auth)
├── apikey         — 64-char hex keys for device auth
├── device         — unique per (user, device_id)
│   ├── location   — lat/lng/point, timestamp, geocoded fields
│   └── trip       — name, start/end time
│       └── tripplace — named waypoint with radius
├── geocodingjob   — one per user, tracks batch progress
└── backupconfig   — s3 credentials, schedule, retention

vector tiles

the map uses postgis-generated mapbox vector tiles. instead of sending thousands of geojson points, the server generates compact binary tiles via ST_AsMVT(). each tile has two layers:

  • locations — individual points
  • trails — connected line strings between consecutive points

tiles are cached for 30 seconds and capped at 100k points per tile.

troubleshooting

docker won't start

  • check docker is running: docker info
  • check port 8001 is free: ss -tlnp | grep 8001
  • view logs: docker compose logs web
  • db issues: docker compose logs db

locations not appearing on the map

  • verify the api key — copy-paste, check for spaces
  • check the key is active in settings
  • check the time range filter — try "all time"
  • test with curl: 
    curl -X POST http://localhost:8001/api/push/ \
  -H "Content-Type: application/json" \
  -d '{
    "api_key": "YOUR_KEY",
    "device_id": "test",
    "latitude": 40.7128,
    "longitude": -74.006
  }'
  • check logs: docker compose logs -f web

gpslogger / owntracks not connecting

  • url must end with /api/push/ — trailing slash required
  • for owntracks: confirm you're using http mode, not mqtt
  • if using https, verify the ssl certificate is valid
  • open the push url in your phone's browser to test reachability

geocoding not working

  • nominatim may be rate-limited — wait a few minutes
  • test connectivity: docker compose exec web curl -s https://nominatim.openstreetmap.org/status

csrf errors behind a reverse proxy

  • set CSRF_TRUSTED_ORIGINS=https://roamly.yourdomain.com
  • confirm your proxy passes X-Forwarded-Proto

"allowed hosts" error

  • set ALLOWED_HOSTS=roamly.yourdomain.com
  • for local access too: ALLOWED_HOSTS=roamly.yourdomain.com,localhost

faq

is roamly actually private?

yes. it runs on your server, no telemetry, no data sharing. the only external call is nominatim for geocoding — which only sends coordinates, no user info.

can multiple people share one instance?

yes. each user gets their own account with separate data, devices, trips, and api keys. no cross-user data access.

how much storage does it use?

a phone sending every 5 minutes generates ~100k points/year, which is roughly 50–100 mb in postgresql. postgis handles millions of points fine.

can i run this on a raspberry pi?

yes. roamly runs on arm64. at least 2 gb ram recommended. the postgis docker image supports arm64.

do i need a domain name?

for remote access over the internet, yes — or use tailscale/vpn for your phone to reach the server. for local network only, an ip address works fine.

what if my server goes down?

gpslogger and owntracks both buffer locations on-device and send them when the connection restores. your existing data is safe on disk in the postgres volume.

can i use it without gpslogger or owntracks?

absolutely. anything that can post json over http works — curl, python, tasker, shortcuts, home assistant, custom apps.

how do i migrate to a new server?

  1. export a full backup: settings → export backup (json)
  2. or dump postgres: docker compose exec db pg_dump -U roamly roamly > backup.sql
  3. set up roamly on the new server
  4. import the backup or restore the sql dump

does roamly support real-time tracking?

locations are stored as they arrive but there's no live-push to the browser. refresh the map to see the latest. gpslogger and owntracks can both send updates every few seconds for near-real-time.
