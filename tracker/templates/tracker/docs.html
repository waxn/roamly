roamly documentation

roamly is a self-hosted location tracking platform that gives you full ownership of your location data. track your devices, visualize journeys on interactive maps, analyze travel patterns, and export everything — all on your own server.

what you get

  • interactive map — visualize location history with maplibre gl and vector tiles, supporting millions of points
  • multi-device tracking — track phones, tablets, or any device that can send http requests
  • trip management — organize locations into named trips with places and time-spent tracking
  • visit analytics — see which cities, states, and countries you've visited with time spent at each
  • distance tracking — daily distance calculations with canvas-based charts
  • reverse geocoding — automatic conversion of coordinates to place names via openstreetmap nominatim
  • import & export — full data portability with csv, gpx, and json backup formats
  • automatic s3 backups — scheduled backups to any s3-compatible storage with configurable retention
  • owntracks compatible — native support for owntracks http mode
  • api key auth — secure api keys for each device, manageable from the web ui
  • pwa support — installable as a progressive web app with offline capabilities
  • dark & light themes — toggle between themes from the settings page

tech stack

  • backend: django 5 + python 3.12, gunicorn
  • database: postgresql 16 with postgis for spatial queries and vector tiles
  • frontend: vanilla javascript, maplibre gl, canvas api charts
  • deployment: docker & docker compose

docker setup

roamly is deployed with docker compose. the stack includes a postgis database and the django web application — everything is configured out of the box.

prerequisites

  • docker and docker compose installed on your system
  • at least 2 gb ram and 1 gb free disk space
  • ports 8001 (web) and optionally 5433 (database) available

install & run

# clone the repository
git clone https://github.com/waxn/roamly.git
cd roamly

# start the stack (database + web app)
docker compose up -d
that's it! roamly is now running at http://localhost:8001. migrations and static files are handled automatically on startup.

what docker compose starts

service image port description
db postgis/postgis:16-3.4 5433 → 5432 postgresql database with postgis spatial extensions
web built from Dockerfile 8001 → 8000 django app served by gunicorn (3 workers)

data persistence

your data is stored in bind-mount volumes that survive container restarts and rebuilds:

  • ./data/postgres/ — all database data (locations, users, trips, etc.)
  • ./staticfiles/ — collected static assets
backup tip: to back up your database, run:
docker compose exec db pg_dump -U roamly roamly > backup.sql

useful commands

# view live logs
docker compose logs -f web

# stop everything
docker compose down

# rebuild after pulling updates
docker compose down && docker compose up -d --build

# open a database shell
docker compose exec db psql -U roamly -d roamly

# back up the database
docker compose exec db pg_dump -U roamly roamly > backup.sql

# restore from backup
docker compose exec -T db psql -U roamly roamly < backup.sql

first steps

after starting roamly with docker compose, follow these steps to start tracking your location.

1

create an account

open http://localhost:8001 and click get started to create your account. enter a username and password — this is your private instance, so there's no email required.

2

create an api key

go to settings and scroll to the api keys section. click create api key and give it a name that matches your device (e.g., "pixel 9", "iphone 16"). copy the generated key — you'll need it in the next step.

3

set up a tracking app

install owntracks on your phone (ios or android). configure it to send locations to your roamly server. see the owntracks setup tutorial for step-by-step instructions.

4

verify it's working

after owntracks sends its first location, go to the map page. you should see a point on the map. if not, check the troubleshooting section.

5

run geocoding

go to settings and click start geocoding to convert your location coordinates into city/country names. this runs in the background and respects nominatim rate limits.

tip: roamly also geocodes new locations automatically as they arrive. the background geocoding job is useful for bulk-processing imported data or locations that were pushed while nominatim was unavailable.

configuration

roamly is configured through environment variables. you can set these in a .env file in the project root, or pass them directly in your docker-compose.yml override.

environment variables

variable description default
DEBUG enable django debug mode. set to False in production. False
SECRET_KEY django secret key for session signing. change this in production. change-me-in-production
POSTGRES_PASSWORD password for the postgresql database user. roamly_secret
ALLOWED_HOSTS comma-separated list of hostnames the server accepts requests for. *
CSRF_TRUSTED_ORIGINS comma-separated urls trusted for csrf. required when behind a reverse proxy. http://localhost,http://127.0.0.1
DATABASE_URL full database connection string. auto-configured in docker compose. postgis://roamly:...@db:5432/roamly

example .env file

# production .env file
SECRET_KEY=your-random-secret-key-at-least-50-chars
POSTGRES_PASSWORD=a-strong-database-password
ALLOWED_HOSTS=roamly.yourdomain.com
CSRF_TRUSTED_ORIGINS=https://roamly.yourdomain.com
DEBUG=False
important: always change SECRET_KEY and POSTGRES_PASSWORD before exposing roamly to the internet. the defaults are insecure placeholders.

generating a secret key

# run this to generate a secure random key
python3 -c "import secrets; print(secrets.token_urlsafe(64))"

owntracks setup

owntracks is a free, open-source app for ios and android that sends your location to your own server. it's the recommended way to push locations to roamly.

install owntracks

  • ios: download from app store
  • android: download from google play or f-droid

step-by-step configuration

1

get your api key from roamly

log into roamly → settings → api keys → create api key. name it after your phone model. copy the 64-character key.

2

open owntracks preferences

android: tap the menu (☰) → preferences → connection
ios: tap (i) button → settings

3

set mode to http

change the mode from mqtt to http. this tells owntracks to send location updates over http(s) instead of mqtt.

4

set the server url

enter your roamly push endpoint:

https://your-domain.com/api/push/?api_key=YOUR_API_KEY

replace your-domain.com with your server address and YOUR_API_KEY with the key you copied.

for local testing (phone and server on same network):

http://192.168.x.x:8001/api/push/?api_key=YOUR_API_KEY
5

set your device identifier

in owntracks preferences, set the tracker id (tid) to a short name like ph or your initials. this is used as the device id in roamly.

6

send a test location

go back to the owntracks map screen and tap the publish button (↑) to force-send your current location. then check roamly's map page — your point should appear within a few seconds.

alternative auth: instead of passing the api key in the url, you can set an authorization header in owntracks: Authorization: Bearer YOUR_API_KEY. the url parameter method is simpler for most users.

recommended owntracks settings

  • monitoring mode: "significant" for battery-friendly tracking, "move" for detailed tracking
  • location accuracy: owntracks reports gps accuracy — roamly stores this per point
  • battery data: automatically captured and stored with each location point

owntracks not working?

  • make sure the url ends with /api/push/ (trailing slash matters in django)
  • check that you're using http mode, not mqtt
  • verify the api key has no extra spaces (copy-paste carefully)
  • check that your roamly server is reachable from your phone's network
  • look at logs: docker compose logs -f web

sending locations

you can push location data to roamly from any app or script that can make http requests. the /api/push/ endpoint accepts json payloads.

authentication

every push request needs an api key. you can pass it in three ways (in order of preference):

  1. authorization header: Authorization: Bearer YOUR_API_KEY
  2. url parameter: ?api_key=YOUR_API_KEY
  3. json body field: {"api_key": "YOUR_API_KEY", ...}

standard format

curl -X POST https://your-domain.com/api/push/ \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "my-phone",
    "latitude": 48.8566,
    "longitude": 2.3522,
    "timestamp": "2026-01-15T14:30:00Z",
    "altitude": 35.0,
    "accuracy": 5.0,
    "speed": 1.2,
    "battery": 85
  }'

field reference

field type required description
device_id string yes unique identifier for the device
latitude number yes latitude in decimal degrees (-90 to 90)
longitude number yes longitude in decimal degrees (-180 to 180)
timestamp string / number no iso 8601 string or unix timestamp. defaults to current time.
altitude number no altitude in meters
accuracy number no gps accuracy in meters
speed number no speed in meters per second
battery number no battery percentage (0–100)

owntracks format

roamly also accepts the native owntracks json format:

{
  "_type": "location",
  "tid": "ph",
  "lat": 48.8566,
  "lon": 2.3522,
  "tst": 1705325400,
  "alt": 35,
  "acc": 5,
  "vel": 4,
  "batt": 85
}

response

// success (200)
{
  "status": "ok",
  "location_id": 12345,
  "device": "my-phone"
}

// error (401)
{
  "error": "Invalid or missing API key"
}

example: python script

import requests
import time

API_KEY = "your-api-key-here"
URL = "https://your-domain.com/api/push/"

data = {
    "device_id": "python-script",
    "latitude": 51.5074,
    "longitude": -0.1278,
    "timestamp": int(time.time())
}

response = requests.post(
    URL,
    json=data,
    headers={"Authorization": f"Bearer {API_KEY}"}
)
print(response.json())

managing trips

trips let you organize location data into named journeys — vacations, road trips, business travel, daily commutes. a trip captures all locations within a time range from a specific device.

creating a trip

1

go to the trips page

click trips in the navigation bar.

2

click "create trip"

fill in the form:

  • name — e.g., "tokyo spring 2026"
  • device — which device was with you on the trip
  • start date / end date — the trip's time range
  • description — optional notes about the trip
3

view the trip

click on the trip to open it. you'll see a full-screen map with all location points that fall within the trip's time range, connected by a trail line.

adding places to a trip

places are named waypoints within a trip — hotels, restaurants, landmarks. roamly calculates how long you spent at each place based on nearby location points.

  1. open a trip and click add place
  2. enter a name (e.g., "hotel shinagawa")
  3. set the latitude and longitude (click on the map or enter manually)
  4. set a radius in meters — location points within this radius count as "at this place"
  5. add optional notes
time spent calculation: roamly uses the haversine formula to find which location points fall within a place's radius. it then sums the time gaps between consecutive points (capping gaps at 1 hour) to estimate total time at that place.

editing & deleting trips

  • click on a trip to view/edit its name and description
  • places can be edited or removed individually
  • deleting a trip only removes the trip and its places — your location data is not affected

import & export

your data is yours. export it anytime in open formats, or import location history from other services.

exporting data

all export options are available in settings.

csv export

downloads all locations as a spreadsheet-compatible csv file with columns: device, latitude, longitude, altitude, accuracy, speed, battery, timestamp, city, state, country, country_code.

gpx export

downloads locations in gpx 1.1 format — compatible with google earth, qgis, garmin basecamp, and most gps software. includes elevation data when available.

full backup (json)

exports everything: devices, locations, trips, places, and api keys in a single json file. use this to migrate between servers or as a complete backup.

importing data

csv import

upload a csv file with location data. roamly flexibly detects columns — it understands variations like lat/latitude, lng/lon/longitude, etc. minimum required columns are latitude, longitude, and timestamp.

gpx import

upload gpx files from any gps app or device. roamly reads track points, route points, and waypoints from both gpx 1.0 and 1.1 formats.

restore from backup

upload a roamly json backup file to restore all data. this runs in an atomic transaction — if anything fails, nothing is partially imported. duplicate locations are automatically skipped.

note on google takeout: google location history exports are in a non-standard format. convert them to csv or gpx first using a third-party tool before importing into roamly.

geocoding

reverse geocoding converts raw coordinates into readable place names (city, state, country). roamly uses openstreetmap nominatim, a free geocoding service.

how it works

  • real-time: when a new location is pushed via the api, roamly immediately attempts to geocode it
  • background batch: for bulk imports or failed geocoding attempts, you can run a background job from settings

running background geocoding

  1. go to settings
  2. click start geocoding
  3. roamly processes un-geocoded locations in batches of 500, with a 1.1-second pause between requests (to respect nominatim rate limits)
  4. progress is shown live — you can refresh to check, or click stop to pause
rate limits: nominatim allows 1 request per second. roamly throttles automatically. for 10,000 un-geocoded locations, expect about 3 hours of processing time.

what gets stored

each geocoded location receives:

  • city — city, town, village, or municipality name
  • state — state, province, or region
  • country — full country name
  • country_code — iso 3166-1 alpha-2 code (e.g., "us", "de")
  • place_name — full display name from nominatim

automatic backups

roamly can automatically back up all your data to any s3-compatible storage provider — aws s3, backblaze b2, cloudflare r2, minio, wasabi, or any service that speaks the s3 api.

supported providers

provider endpoint url
aws s3 https://s3.amazonaws.com (or regional, e.g. https://s3.us-east-1.amazonaws.com)
backblaze b2 https://s3.us-west-000.backblazeb2.com (check your bucket region)
cloudflare r2 https://<account-id>.r2.cloudflarestorage.com
minio http://your-minio-server:9000
wasabi https://s3.wasabisys.com (or regional)

setting up automatic backups

1

create a bucket

create a bucket in your s3 provider's dashboard. note the bucket name, endpoint url, and region.

2

get access credentials

create an access key and secret key with read/write permissions for the bucket. most providers have an "application keys" or "iam" section for this.

3

configure in roamly

go to settings → automatic backups and fill in:

  • endpoint url — your provider's s3 endpoint
  • bucket name — the bucket you created
  • access key and secret key — your credentials
  • path prefix — folder path inside the bucket (default: roamly-backups/)
  • region — bucket region (default: auto)
4

test the connection

click test connection to verify your credentials. roamly uploads and deletes a small test file to confirm everything works.

5

set a schedule

choose a backup interval: daily, weekly, or monthly. click save. backups will run automatically in the background.

backup retention

set max backups to keep to automatically delete older backups when the limit is exceeded. set to 0 for unlimited retention. after each successful backup, roamly lists all backup files in your bucket prefix and removes the oldest ones beyond the limit.

manual backups

click backup now to trigger an immediate backup at any time. the backup runs in the background — you can see progress and status in the settings page.

backup format

backups use the same json format as the manual export. each backup file contains all your devices, locations, trips, places, and api keys. files are named:

{prefix}{username}/backup_{YYYY-MM-DD_HHmmss}.json

for example: roamly-backups/alice/backup_2026-02-17_143022.json

restoring from an s3 backup

  1. download the backup json file from your s3 bucket
  2. go to settings → import → restore from backup
  3. upload the json file — roamly restores everything in an atomic transaction
tip: the backup scheduler checks every 15 minutes whether a backup is due. so a "daily" backup won't run at exactly the same time each day, but within a 15-minute window of when the interval elapses.

reverse proxy

for production use, put roamly behind a reverse proxy for https support and proper domain routing.

nginx configuration

server {
    listen 80;
    server_name roamly.yourdomain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name roamly.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/roamly.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/roamly.yourdomain.com/privkey.pem;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

ssl with let's encrypt

# install certbot
sudo apt install certbot python3-certbot-nginx

# get a certificate
sudo certbot --nginx -d roamly.yourdomain.com

# auto-renewal is set up automatically by certbot
don't forget: update your .env file when using a reverse proxy: 
ALLOWED_HOSTS=roamly.yourdomain.com
CSRF_TRUSTED_ORIGINS=https://roamly.yourdomain.com

caddy (alternative)

caddy handles ssl automatically with zero configuration:

# Caddyfile
roamly.yourdomain.com {
    reverse_proxy localhost:8001
}

security

production checklist

  • set DEBUG=False
  • change SECRET_KEY to a random string (50+ characters)
  • change POSTGRES_PASSWORD to a strong password
  • set ALLOWED_HOSTS to your domain only (not *)
  • set CSRF_TRUSTED_ORIGINS to your https url
  • use https via a reverse proxy (nginx/caddy + let's encrypt)
  • don't expose port 5433 (database) to the internet — only expose 8001 or use the reverse proxy

api key best practices

  • create a separate api key for each device
  • deactivate keys you're no longer using (toggle in settings)
  • delete keys for devices you've retired
  • roamly tracks when each key was last used — check periodically

account & data deletion

from settings, you can:

  • delete all location data — removes all locations while keeping your account, devices, and trips
  • delete account — permanently removes your account and all associated data

updating roamly

to update to the latest version:

# pull the latest code
cd roamly
git pull

# rebuild and restart
docker compose down
docker compose up -d --build

migrations run automatically on startup, so your database schema will be updated as needed.

before updating: it's a good idea to back up your database first:
docker compose exec db pg_dump -U roamly roamly > backup_$(date +%Y%m%d).sql

data model

user (django auth)
├── apikey          — 64-char hex keys for device auth
├── device          — unique per (user, device_id)
│   ├── location    — lat/lng/point, timestamp, geocoded fields
│   └── trip        — name, start/end time
│       └── tripplace  — named waypoint with radius
├── geocodingjob    — one per user, tracks batch progress
├── poidownloadjob  — one per user, tracks poi download progress
└── backupconfig    — s3 credentials, schedule, retention limit

vector tiles

the map uses postgis-generated mapbox vector tiles for fast rendering. instead of sending thousands of geojson points to the browser, the server generates compact binary tiles on-demand using ST_AsMVT(). each tile contains two layers:

  • locations — individual points
  • trails — connected line strings between consecutive points

tiles are cached for 30 seconds and limited to 100k points per tile to prevent memory issues.

troubleshooting

docker won't start

  • check docker is running: docker info
  • check port 8001 is free: ss -tlnp | grep 8001
  • view logs: docker compose logs web
  • if the database container is unhealthy: docker compose logs db

locations not appearing on the map

  • verify your api key is correct: copy-paste it, check for trailing spaces
  • verify the key is active (not deactivated) in settings
  • check the time range filter on the map — try "all time"
  • test with curl: 
    curl -X POST http://localhost:8001/api/push/ \
  -H "Content-Type: application/json" \
  -d '{
    "api_key": "YOUR_KEY",
    "device_id": "test",
    "latitude": 40.7128,
    "longitude": -74.006
  }'
  • check logs for errors: docker compose logs -f web

owntracks shows "not connected" or fails to publish

  • make sure you're using http mode, not mqtt
  • verify the url ends with /api/push/ (trailing slash required)
  • if using https, make sure your ssl certificate is valid
  • test if the server is reachable from your phone (try opening the url in your phone's browser)

geocoding not working

  • nominatim may be temporarily rate-limited — wait a few minutes and try again
  • check server has internet access: docker compose exec web curl -s https://nominatim.openstreetmap.org/status
  • check geocoding job status in settings

csrf errors when behind a reverse proxy

  • set CSRF_TRUSTED_ORIGINS to include your full url (e.g., https://roamly.yourdomain.com)
  • make sure your proxy passes the X-Forwarded-Proto header

"allowed hosts" error

  • set ALLOWED_HOSTS to include your domain: ALLOWED_HOSTS=roamly.yourdomain.com
  • for local access, include localhost: ALLOWED_HOSTS=roamly.yourdomain.com,localhost

frequently asked questions

is roamly truly private?

yes. roamly runs entirely on your server. there is no telemetry, no tracking, no data sharing. the only external service contacted is openstreetmap nominatim for geocoding, and that only sends coordinates (no user info).

can multiple people use one roamly instance?

yes. each user signs up with their own account and gets separate data, devices, trips, and api keys. there is no cross-user data access.

how much storage does it use?

very little. a typical phone sending a location every 5 minutes generates around 100k points per year, which takes roughly 50–100 mb in postgresql. even with millions of points, roamly handles it well thanks to postgis indexing and vector tiles.

can i run this on a raspberry pi?

yes, roamly runs on arm devices. make sure you have at least 2 gb ram. the postgis docker image supports arm64.

do i need a domain name?

for owntracks over the internet, yes — you need either a domain with https or a way for your phone to reach your server (e.g., vpn, tailscale). for local network only, you can use your server's ip address.

what happens if my server goes down?

owntracks buffers locations on-device and sends them when the connection is restored. your existing data is safe in the postgresql volume on disk.

can i use this without owntracks?

absolutely. any tool that can send http post requests works — curl, python scripts, tasker, shortcuts, home assistant, or any custom app. see the sending locations tutorial.

how do i migrate to a new server?

  1. export a full backup: settings → export backup
  2. or dump the database: docker compose exec db pg_dump -U roamly roamly > backup.sql
  3. set up roamly on the new server
  4. restore the backup or import the sql dump

does roamly support real-time tracking?

roamly stores locations as they arrive but doesn't have a live-updating map (no websockets). refresh the map page to see the latest data. owntracks in "move" mode can send updates every few seconds for near-real-time tracking.

can i customize the map style?

the map uses maplibre gl with an openstreetmap tile provider. the style switches between dark and light based on your theme preference. custom map styles would require editing the template source code.
