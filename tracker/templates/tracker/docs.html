roamly documentation

Welcome to Roamly! This comprehensive guide covers installation, configuration, usage, and advanced features.

what is roamly?

Roamly is a privacy-first, self-hosted location tracking platform. Track your device locations, visualize journeys on interactive maps, analyze travel patterns, and maintain complete control over your data. No third-party tracking companies, no data selling—just you and your server.

key features

  • Multi-device tracking: Track multiple phones, tablets, or other devices from a single account
  • Interactive maps: Visualize your location history on beautiful, responsive maps
  • Trip management: Create named trips and organize locations by journey
  • Visit detection: Automatically identify places you visit frequently
  • Statistics: Comprehensive travel analytics—distance, countries/cities visited, time spent
  • API key authentication: Securely push locations from mobile apps via API keys
  • Export/Import: Full data portability via CSV and GPX formats
  • Reverse geocoding: Automatic conversion of coordinates to readable place names
  • PostGIS spatial support: Optional advanced geospatial queries
  • OwnTracks integration: Works natively with OwnTracks and compatible apps

technology stack

  • Backend: Django 5.0+, Python 3.12+
  • Databases: PostgreSQL (recommended) + PostGIS, SQLite (fallback)
  • Server: Gunicorn WSGI application server
  • Frontend: HTML5, JavaScript, Leaflet.js map library
  • Containerization: Docker & Docker Compose (optional)

quick start

Get Roamly running in minutes using Docker (recommended).

using docker (easiest)

Recommended approach: Docker handles all dependencies and configuration automatically.

Prerequisites: Docker and Docker Compose installed

# Clone the repository
git clone https://github.com/your-org/roamly.git
cd roamly

# Start services
docker-compose up -d

# Create superuser for Django admin
docker-compose exec web python manage.py createsuperuser

# Access the app
# Web: http://localhost:8001
# Database: localhost:5433

That's it! Roamly is now running. Visit http://localhost:8001, sign up, and start tracking.

without docker

  1. Install Python 3.12+ and PostgreSQL
  2. Clone and enter the directory
  3. Create a virtual environment: python -m venv venv && source venv/bin/activate
  4. Install dependencies: pip install -r requirements.txt
  5. Configure your database (see Database Configuration section)
  6. Run migrations: python manage.py migrate
  7. Create superuser: python manage.py createsuperuser
  8. Run: python manage.py runserver (development) or use gunicorn for production

system requirements

minimum (sqlite, local development)

  • Python 3.12 or higher
  • 2 GB RAM
  • 100 MB disk space
  • Any OS: Linux, macOS, Windows

recommended (production with postgresql)

  • Python 3.12 or higher
  • PostgreSQL 13+ or PostGIS 16+
  • 4 GB+ RAM
  • Sufficient disk for location history (typically 1-10 GB)
  • Linux server (Ubuntu, Debian, CentOS)

browser support

  • Chrome/Chromium 90+

manual installation

step 1: install dependencies

# Ubuntu/Debian
sudo apt-get update
sudo apt-get install python3.12 python3.12-venv postgresql postgresql-contrib
sudo apt-get install binutils libproj-dev gdal-bin libgdal-dev libgeos-dev

# macOS
brew install python@3.12 postgresql gdal

# Windows: Use WSL or download installers

step 2: clone and setup python

git clone https://github.com/your-org/roamly.git
cd roamly

# Create virtual environment
python3.12 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install Python packages
pip install --upgrade pip
pip install -r requirements.txt

step 3: setup database

# Create PostgreSQL user and database
sudo -u postgres createuser -P roamly    # Enter password when prompted
sudo -u postgres createdb -O roamly roamly

# Generate DATABASE_URL
export DATABASE_URL="postgresql://roamly:your_password@localhost:5432/roamly"

# Run migrations
python manage.py migrate

# Create superuser
python manage.py createsuperuser

step 4: run the application

Development (local testing):

python manage.py runserver

Production (with gunicorn):

pip install gunicorn
gunicorn roamly.wsgi:application --bind 0.0.0.0:8000 --workers 3 --timeout 300

step 5: configure reverse proxy (nginx)

server {
    listen 80;
    server_name yourdomain.com;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /static/ {
        alias /path/to/roamly/staticfiles/;
    }
}

reverse geocoding

overview

Reverse geocoding converts latitude/longitude coordinates into readable addresses and place names. Roamly uses OpenStreetMap's free Nominatim service.

how it works

  1. Location data is received via API push
  2. Coordinates are queued for geocoding
  3. Background task fetches place name from Nominatim
  4. City, state, country, and place name are stored with location
  5. UI displays readable addresses instead of coordinates

configuration

Geocoding is automatic—no configuration needed. Roamly respects Nominatim's rate limits and caches results.

Important: Nominatim ToS requires a User-Agent header. Roamly includes this automatically. Do not change the request headers.

nominatim rate limits

  • Max 1 request per second
  • Max 50,000 requests per day
  • Results are cached to minimize requests

see geocoding status

Check the geocoding background task status via Settings → Geocoding Status in the web UI.

owntracks integration

what is owntracks?

OwnTracks is a free, open-source app available on iOS and Android that sends your location to your own server. Perfect for Roamly.

installation

  • iOS: App Store
  • Android: Google Play or F-Droid

configuration steps

  1. Create API Key in Roamly: Settings → API Keys → Create
  2. Open OwnTracks app
  3. Go to Preferences/Settings
  4. Select "HTTP" mode (not MQTT)
  5. Configure HTTP endpoint:
    • Server: https://yourdomain.com/api/push/
    • Port: 443
    • Authorization: None
  6. In custom headers or URL params, add API key:
    • Header: Authorization: Bearer YOUR_API_KEY
    • OR URL param: ?api_key=YOUR_API_KEY
  7. Enable location tracking
  8. Test: Force a manual publish in OwnTracks (Settings → Publish)

owntracks features in roamly

  • Automatic location updates (configurable interval)
  • Battery optimization
  • WiFi-only mode option
  • Geofencing support (comes through as waypoints)
  • Full payload support—all device data captured

troubleshooting owntracks

Locations not appearing?

  • Check API key is correct (copy/paste, no spaces)
  • Verify server URL is correct and HTTPS accessible
  • Check that location permission is granted to OwnTracks
  • Force OwnTracks to reconnect: Toggle HTTP mode off/on
  • Check Roamly server logs for errors

managing trips

what is a trip?

A trip is a named collection of locations within a specific time frame. Perfect for organizing your journeys—vacations, business trips, road trips, daily commutes.

creating a trip

  1. Go to Trips page in the web interface
  2. Click "Create Trip"
  3. Enter trip name (e.g., "European Vacation")
  4. Select device and date range
  5. Add optional description
  6. Click "Create"

adding places to a trip

  1. Open a trip
  2. Click "Add Place"
  3. Search for place or click on map
  4. Set radius (detection threshold in meters)
  5. Add notes (optional)
  6. Click "Save Place"

viewing trip statistics

  • Map view: See all locations and places on an interactive map
  • Timeline: Sequential view of locations during trip
  • Statistics: Distance traveled, locations count, time spent

trip features

  • Automatic visit detection (was I at place X?)
  • Distance calculation between points
  • Edit trip details after creation
  • Export trip as GPX file
  • Delete trips (data remains in main history)

export and import data

exporting your data

Access exports from the Settings page. Your data is yours—export it anytime in open formats.

csv export

Structured data format compatible with spreadsheet apps and databases.

Columns: device_id, latitude, longitude, timestamp, altitude, accuracy,
speed, battery, city, state, country, country_code, place_name

gpx export

Standard GPS Exchange format for use with mapping software and GPS devices.

Includes all waypoints with metadata. Compatible with:
- Google Earth
- QGIS
- Garmin BaseCamp
- Most GPS software

importing data

Import location history from other services or devices.

from google location history

  1. Go to Google Takeout
  2. Select "Location History" (only this data)
  3. Download the JSON file
  4. In Roamly, Settings → Import → Upload JSON file

from gpx files

  1. Get GPX files from any GPS app or service
  2. In Roamly, Settings → Import GPX
  3. Upload one or multiple .gpx files
  4. Roamly extracts waypoints and creates locations

from csv

  1. Format CSV with columns: latitude, longitude, timestamp
  2. Optional: altitude, accuracy, device_id
  3. In Roamly, Settings → Import CSV
  4. Upload and map columns

data portability

You retain full ownership of your location data. Export anytime, migrate to another service, or archive for personal records.

Privacy guarantee: Your server, your data, your rules. We don't access, log, or analyze user location data.

troubleshooting

docker won't start

Issue: docker-compose up -d fails

Solutions:

  • Check Docker is installed: docker --version
  • Check Docker daemon is running: sudo systemctl start docker
  • View logs: docker-compose logs web
  • Verify port 8001 is free: sudo lsof -i :8001

database connection error

Issue: OperationalError: FATAL: role "roamly" does not exist

Solutions:

  • Create PostgreSQL user: sudo -u postgres createuser -P roamly
  • Create database: sudo -u postgres createdb -O roamly roamly
  • Set DATABASE_URL environment variable correctly
  • Verify credentials: psql -U roamly -d roamly -h localhost

locations not appearing

Issue: Pushed locations from mobile app don't show in web UI

Solutions:

  • Verify API key is copied correctly (no spaces)
  • Check API key is marked "active" in Settings
  • Test push manually: curl -X POST https://yourdomain.com/api/push/ \ -H "Authorization: Bearer YOUR_KEY" \ -H "Content-Type: application/json" \ -d '{"device_id":"test","latitude":40.7,"longitude":-74.0}'
  • View server logs: docker-compose logs -f web
  • Check OwnTracks settings (server URL, bearer token format)

reverse geocoding not working

Issue: Locations don't have city/country names

Solutions:

  • Nominatim may be rate-limited. Wait a few minutes.
  • Check geocoding status: Settings → Geocoding Status
  • Verify internet connectivity on server
  • Check firewall allows outbound HTTPS (port 443)

high memory usage

Issue: Server uses excessive RAM

Solutions:

  • Limit gunicorn workers: --workers 2 instead of 3+
  • Check for memory leaks in logs
  • Reduce location history kept (archive old data)
  • Upgrade server RAM if needed

ssl certificate errors

Issue: HTTPS connections fail

Solutions:

  • Verify cert exists: ls /etc/letsencrypt/live/yourdomain.com/
  • Renew cert: sudo certbot renew
  • Check certificate expiry: openssl x509 -in /path/to/cert -noout -dates
  • Verify nginx config: sudo nginx -t

migrationerrors after update

Issue: Migrations fail after code update

Solutions:

  • View migration status: python manage.py showmigrations
  • Run all pending migrations: python manage.py migrate
  • Rollback to previous migration if needed: python manage.py migrate tracker 0001

frequently asked questions

general

is roamly truly private?

Yes. Roamly runs entirely on your server. No telemetry, no tracking, no data sharing. Your location data never leaves your infrastructure unless you explicitly export it.

can i host roamly for multiple people?

Yes! Each user gets an account with their own API keys and view. Perfect for families or teams sharing a server.

what happens if i stop tracking?

Your data remains in the database. You can start again anytime—no data loss.

how much data can roamly store?

Theoretically unlimited (depends on disk space). A typical smartphone generates 1-2 MB of location data per year. Roamly efficiently indexes and queries this data.

installation & setup

do i need a domain?

For production (HTTPS), yes. Use a free domain from Freenom or similar if needed. Or use a dynamic DNS service if your IP changes.

is docker required?

No, but recommended. Manual installation works fine if you're comfortable with command line.

can i run this on raspberry pi?

Yes! Roamly works on low-power devices. Use SQLite for the database on small devices.

what's the minimum postgres version?

PostgreSQL 12+. For PostGIS features, PostGIS 3.0+.

mobile & tracking

what's the best interval for sending locations?

Depends on your needs:

  • 5-10 min: Detailed tracking, higher battery drain
  • 30 min: Good balance
  • 1 hour+: Minimal battery impact
OwnTracks lets you set custom intervals.

does tracking work offline?

Most apps buffer locations and send when connection returns. OwnTracks does this automatically.

how much battery does tracking use?

Depends on GPS frequency. With OwnTracks at 30-min intervals, expect 10-20% extra battery drain.

can i track without owntracks?

Yes! Any app that sends HTTPS POST requests works. The location API accepts standard JSON format.

data & privacy

can i share my location with others?

Not built-in, but you can:

  • Export data and share files
  • Show specific trips/maps to others
  • Create a separate account for shared devices

how do i delete my data?

User data can be deleted via account deletion or by removing locations in Django admin. Deleting your account removes all personal info.

is my data encrypted at rest?

Database encryption depends on your PostgreSQL setup. Enable it with: --with-openssl flag during PostgreSQL build.

does roamly call external services?

Only Nominatim (OpenStreetMap) for reverse geocoding. All requests include a proper User-Agent and respect ToS and rate limits.

performance & scaling

how many locations can roamly handle?

Millions easily. PostgreSQL with proper indexing handles billions of points. Performance depends on query complexity.

what's the recommended hardware?

Small (up to 100K locations): 2GB RAM, 10GB disk
Medium (up to 10M locations): 4GB RAM, 100GB disk, SSD recommended
Large (10M+ locations): 8GB+ RAM, NVMe SSD, dedicated PostgreSQL server

how do i back up my data?

docker-compose exec db pg_dump -U roamly roamly > backup.sql
# Or for manual PostgreSQL:
pg_dump roamly -U roamly > backup.sql

can i migrate from one server to another?

Yes! Export database with pg_dump, restore on new server, copy staticfiles folder.

development & customization

is the source code available?

Yes, Roamly is open source. Modify and extend it for your needs.

can i add custom features?

Absolutely. The codebase is modular. Common customizations:

  • Custom map tiles or overlays
  • Additional statistics or analytics
  • Integration with other services
  • Custom authentication

how do i contribute?

Fork the repository, make improvements, submit a pull request. All contributions welcome!
