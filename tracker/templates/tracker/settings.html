Reverse Geocoding
Label un-geocoded points with city/country using local TIGER data. Runs automatically on new points.
Match POIs to Points
Label every GPS point with the nearest named place (store, café, park, …) so it shows in the data table's Place column. Uses the instance's downloaded POIs (Admin Panel → Downloads — ask an instance admin if none exist yet). Re-run any time to refresh after more POIs are downloaded.
Detect Transport Modes
Work out how you were moving — still, walk, cycle, vehicle or plane — and show the split on the Stats page. Your track is cut into journeys at each long stop and scored as a whole, so a red light stays part of the drive. Re-run any time; it recomputes from scratch.
Recalculate Stats
The Stats, Visits and Places pages are served from a snapshot that refreshes automatically every night. Recompute it now to pick up the latest data immediately.
Road Snapping per-account

GPS scatter puts recorded points beside the road instead of on it. Snapping draws them where they belong, and is what makes Trip Lines Mode follow road curvature instead of cutting straight between points. It is display-only — your recorded coordinates are never modified.

Only road journeys are snapped — walking is left exactly as recorded, so a garden or footpath keeps its detail. Running Detect Transport Modes above makes that decision more accurate: without it the split is guessed from speed, with it each journey is classified as a whole.

Advanced — road data provider

Auto handles this for almost everyone: it uses the road data downloaded onto this server if there is any, and falls back to Mapbox if you have a token. Only change this if you run your own routing engine.

GPSLogger for Android Setup

GPSLogger is a free, open-source Android app for logging GPS data. Here's how to set it up with Roamly:

  1. Install GPSLogger from F-Droid or Google Play
  2. Create an API key below and copy it
  3. In GPSLogger, tap the three-dot menu and go to Logging Details
    • Enable Log to custom URL
  4. Tap Log to custom URL to configure:
    • URL: {{ request.scheme }}://{{ request.get_host }}/api/push/
    • HTTP Method: POST
    • HTTP Body: {"api_key":"YOUR_API_KEY","device_id":"%SER","latitude":%LAT,"longitude":%LON,"altitude":%ALT,"speed":%SPD,"accuracy":%ACC,"battery":%BATT,"timestamp":"%TIME"}
    • HTTP Headers: Content-Type: application/json
  5. Go back, tap Performance, and set your logging interval (e.g. 60 seconds)
  6. Tap the Start button to begin logging

API Usage

Push location data using any HTTP client. Example: 

# API key in JSON body
curl -X POST {{ request.scheme }}://{{ request.get_host }}/api/push/ \
  -H "Content-Type: application/json" \
  -d '{"api_key": "YOUR_API_KEY", "device_id": "my-phone", "latitude": 45.5, "longitude": -122.6}'

# API key in header
curl -X POST {{ request.scheme }}://{{ request.get_host }}/api/push/ \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"device_id": "my-phone", "latitude": 45.5, "longitude": -122.6}'

# OwnTracks format (auto-detected)
curl -X POST {{ request.scheme }}://{{ request.get_host }}/api/push/ \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"_type": "location", "lat": 45.5, "lon": -122.6, "tst": 1234567890, "tid": "phone"}'
